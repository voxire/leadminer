# 249 — `cmd_score` hostile-input audit (`cli.py:247-277`)

## Verdict

The re-scoring *arithmetic* is in good shape: every unicode, emoji, NFD-combining-mark,
whitespace, zero, negative and wildly out-of-range cell I threw at it either round-tripped
correctly or was coerced to `None` without a traceback, and three consecutive in-place passes
produced byte-identical output. The problem is everything around the arithmetic. `cmd_score` is
the only subcommand that **writes to the operator's data**, it defaults to that destructive write
(`cli.py:274`), it validates nothing about the schema it is handed, and it rewrites three fields
it never counts as changed. Three input classes kill it with a raw Python traceback — one of
which also kills the weekly `leadminer run`, because both share `main.load_master` — and the
single most dangerous input, a master CSV carrying any column outside the 22-field `FIELDS` set,
destroys that column permanently while printing a success message and exiting 0.

**Method.** All results below are reproduced against `cli.cmd_score` with a stubbed `requests`
module injected into `sys.modules` (no network; `requests` is in fact absent from this checkout,
which is itself finding S3-1). `main.DATA_DIR` and all scratch CSVs were redirected to a
`tempfile.mkdtemp()` directory outside the repo. No repo file was modified. Repro skeleton:

```python
import argparse, csv, sys, tempfile, os
sys.path.insert(0, "<repo>")
import cli  # after stubbing sys.modules["requests"]
FIELDS = main.FIELDS
# write a 1-row CSV to a tmpdir, then:
cli.cmd_score(argparse.Namespace(file=str(tmp_csv), out=str(tmp_csv)))
```

## Findings

### S1 — One `inf` cell in the master kills both `leadminer score` *and* the weekly `leadminer run`

- **Where:** `main.py:96-101` (`int(float(row[field]))` at `:99`, `except (ValueError, TypeError)` at
  `:100`), reached from `cli.py:259` and from `main.py:150`.
- **Contract violated:** `docs/audits/037-cli-design.md:338` — *"`review_count`,
  `completeness_score`, `lead_score` must be parseable as `int` or `None`"*; and `:310` — exit
  code `1` for *"malformed numeric fields"*.
- **Breaks:** `OverflowError` is a subclass of `ArithmeticError`, not of `ValueError` or
  `TypeError`, so it escapes the handler. `nan` is caught (it raises `ValueError`) and becomes
  `None`; `inf` is not caught at all. The asymmetry is the bug: the function is *almost* total.
- **Trigger — one cell, three columns, three equivalent spellings:**
  ```
  review_count,completeness_score,lead_score
  inf,,        1e400,,         1e309,
  ```
  ```python
  main.load_master(Path("poisoned.csv"))
  # OverflowError: cannot convert float infinity to integer
  ```
  Verified for all three of `_INT_FIELDS` and for the literals `inf` and `1e400`.
- **Blast radius:** `main.main()` calls the *same* `load_master` on the master at `main.py:150`,
  before a single scraper runs. A master carrying one `inf` therefore kills the entire scheduled
  6-hour job at `.github/workflows/scrape.yml:69` — not just the offline scoring tool. Because
  `data/` is gitignored (`.gitignore:5`), the fix is a manual Drive restore.
- **Fix:** widen the handler to `except (ValueError, TypeError, OverflowError)` — or better,
  replace the `int(float(x))` idiom with a single `_to_int` helper that also rejects `inf`/`nan`
  via `math.isfinite`, and reuse it for the float fields. Then wrap the `load_master` call in
  `cmd_score` so one bad row is quarantined rather than killing the run.

### S1 — In-place rewrite silently drops every column outside `FIELDS`, and reports success

- **Where:** `cli.py:274` (`out = pathlib.Path(args.out) if args.out else path`) with
  `cli.py:275` (`pipeline.write_csv(out, records)`), discarding at `main.py:125`
  (`csv.DictWriter(f, fieldnames=FIELDS, extrasaction="ignore")`).
- **Breaks:** `load_master` keys rows off whatever header the input file has
  (`main.py:87`), so extra columns survive into the record dicts. `write_csv` then silently drops
  every key not in the 22-field `FIELDS`. With the default `--out`-less invocation the dropped
  columns are gone from the file *and* there is no snapshot.
- **Trigger:**
  ```
  # all_businesses.csv has been through Google Sheets and a rep added two columns
  name,...,source,scraped_at,notes,enriched_at
  Cafeilia,...,google_places,2026-01-01...,call back tuesday,2026-02-02
  ```
  ```python
  cli.cmd_score(argparse.Namespace(file="all_businesses.csv", out=None))
  # stdout: "re-scored 1 records, 1 changed -> all_businesses.csv"
  # rc=0;  'notes' in header -> False;  'enriched_at' in header -> False
  ```
- **Why this input is not hypothetical:** `data/` is a *bidirectional* mirror of the human sales
  folder. `.github/workflows/scrape.yml:56` does `rclone copy "gdrive:leads/" data/` (downloads
  every `*.csv` the humans own) and `:89` does `rclone copy data/ "gdrive:leads/"` (uploads back).
  A rep adding `notes`/`owner`/`stage` in Sheets and saving puts those columns straight back into
  `data/`. And this is exactly when you would run `score`: after a scoring-rule change — which is
  also when a new column exists.
- **Related, same root cause — the design doc blessed it.** `037-cli-design.md:296-297` specifies
  `--output` defaulting to a **new** file (`data/scored.csv`), preserving the input. The
  implementation inverted that safety default. Worse, `037-cli-design.md:510` gives as a worked
  example: `leadminer score -i data/sa_enriched.csv -o data/all_businesses.csv`. Verified: that
  command replaces a 50-row master with a 1-row file and exits 0.
- **Fix:** (a) make `--out` required, or default it to `path.with_suffix(".rescored.csv")`;
  (b) reject any input whose header is not exactly `set(FIELDS)` — or, if extra columns must be
  tolerated, preserve them instead of dropping them; (c) add `--dry-run`; (d) copy the input to
  `<out>.bak` before the first destructive write; (e) refuse `--out` when the output is a known
  export name and the input is a different, smaller export.
- **Note on prior art:** `docs/audits/200-fn-cli-py-main-ops.md:300-313` reports this same
  `cli.py:274` line as **S3**. I disagree with the severity and the reasoning: the report frames
  it as "the previous *scores* are gone, the write is atomic, no corruption". The loss here is not
  the scores — `cmd_score`'s entire purpose is to replace those, and they are recomputable. The
  loss is **columns that exist nowhere else** (sales notes, ownership, stage), which are not
  recomputable, are not in git, and are then uploaded over Drive by the next weekly run. That is
  silent permanent data loss, which the brief's table puts at S1.

### S2 — `country` is stamped `LB` while `region` still says `Riyadh`, and the contradiction is persisted

- **Where:** `cli.py:266` (`r["country"] = pipeline.resolve_country(r)`) with `main.py:68-74`;
  no region re-inference follows.
- **Breaks:** `resolve_country` falls back to `_DEFAULT_COUNTRY = "LB"` (`main.py:47,74`) for any
  record whose `country` cell is blank and whose phone contains neither `+966`/`00966` nor
  `+961`/`00961`. `cmd_score` never re-runs `infer_region`, so `region` is left exactly as it was.
  The written record is now internally contradictory.
- **Trigger:**
  ```
  name,country,region,lat,lon,phone
  Riyadh Clinic,,Riyadh,24.71,46.68,0112345678
  ```
  ```python
  cli.cmd_score(argparse.Namespace(file=f, out=f))   # in place
  # -> country='LB'  region='Riyadh'   rc=0, no warning
  ```
- **Why it matters here specifically:** `resolve_country`'s own docstring (`main.py:53-57`) states
  that *most* existing master rows have a blank `country` cell because `load_master` turns `""`
  into `None` and the old `record.get("country", "LB")` default therefore never fired. So the
  first `leadminer score` an operator ever runs stamps `LB` onto every one of them, in place.
  Downstream, the next `enrich()` (`enricher.py:332-335`) passes that wrong `country` to
  `infer_region`, which then checks the **Lebanon** coordinate boxes (`enricher.py:90`) against
  Riyadh coordinates and returns `None` — silently erasing a correct region.
- **Fix:** do not let `cmd_score` write `country` unless it changed under an explicit
  `--recompute-country` flag; or, if it must, also re-run `infer_region` and refuse to write when
  the derived country and the recorded region disagree. Best of all, record the *reason*
  (`country_source` = `explicit` | `phone` | `default`) so a default is never mistaken for a fact.

### S2 — Four of the five exports are left stale; the file sales works from now contradicts the master

- **Where:** `cli.py:275` — exactly one `write_csv` call.
- **Breaks:** `cmd_score` rewrites `country`, `industry_priority`, `recommended_service` and
  `lead_score` in whatever single file it was given. `qualified_businesses.csv`,
  `with_websites.csv`, `without_websites.csv` and `sales_ready.csv` keep the *old* values. Those
  four are filtered on `industry_priority` and `completeness_score` (`main.py:199-213`), both of
  which `cmd_score` touches or should touch.
- **Trigger:** after a `_RTYLR_TARGETS` or `PRIORITY_INDUSTRIES` edit, run
  `leadminer score data/all_businesses.csv`. A business that moved from `low` to `high` priority
  is now `high` in the master but still excluded from `sales_ready.csv`. `cmd_stats` defaults to
  `all_businesses.csv` (`cli.py:294`), so the one command an operator would run to check looks
  perfectly consistent. The contradiction is only visible by opening a different file.
- **Fix:** either re-derive all five exports in the same invocation, or refuse to write unless
  `--out` names a non-master path and print an explicit warning naming the four sibling files that
  are now out of date.

### S2 — `"N changed"` counts one field out of four, so it actively misdirects

- **Where:** `cli.py:270-271` (`if new != r.get("lead_score"): changed += 1`), printed at
  `cli.py:276`.
- **Breaks:** `cmd_score` assigns four fields per record (`cli.py:266-272`) but the counter
  compares only `lead_score`. A run that rewrites every `country`, `industry_priority` and
  `recommended_service` in the file can report `0 changed`.
- **Trigger:** take a `cmd_score` output, set `industry_priority="low"`,
  `recommended_service="STALE"` and `country=""`, leave `lead_score` at its now-correct value,
  re-run:
  ```
  stdout: re-scored 1 records, 0 changed -> a3o.csv
  on disk: recommended_service 'STALE' -> 'RTYLR commerce OS (POS, online ordering, CRM)'
           country '' -> 'LB'   industry_priority 'high' -> 'high'
  ```
  The operator reads "0 changed", concludes the file was untouched, and ships the rewritten
  pitch column to the sales team.
- **Fix:** count per-field deltas and report them (`N records, M lead_score, P priority, Q pitch,
  R country changed`), and make the message say explicitly that the file is always rewritten.

### S2 — A single cell over 128 KiB crashes on `csv`'s default field limit

- **Where:** `main.py:86` (`csv.DictReader(f)` inside `load_master`); no `csv.field_size_limit`
  call exists anywhere in the repo.
- **Breaks:** `_csv.Error: field larger than field limit (131072)`. Boundary measured exactly:
  131 072 chars passes, 131 073 crashes.
- **Trigger:** an operator cleaning the master in Excel/Sheets pastes a scraped page, a `<style>`
  block or a Google Maps `place_id` dump into `address`. 128 KiB is ~128 000 characters — one
  long page of HTML, easily pasted, and this project has no schema guard on `address`.
- **Blast radius:** same shared `load_master` as S1-1, so this also aborts the scheduled run at
  `scrape.yml:69`. No temp file is left behind, but no output is produced either.
- **Fix:** `csv.field_size_limit(2**20)` once at import in `main.py`, plus catch `_csv.Error`
  around the `DictReader` loop in `load_master` and fail with the offending line number instead of
  a bare traceback.

### S3 — `cmd_score` never recomputes `completeness_score`, which is the one thing the design doc says it is for

- **Where:** `cli.py:265-272` omits `enricher.completeness_score`.
- **Contract violated:** `037-cli-design.md:303` — *"Evaluates and assigns `completeness_score`
  (`enricher.py:101-117`)"*, listed as step 1 of 4.
- **Breaks:** `cmd_score` cannot roll out a change to the completeness rules. `completeness_score`
  is the filter predicate for `qualified_businesses.csv` (`main.py:206`), so a re-score leaves
  that export keyed to a rule that no longer exists in the code.
- **Accurate blast radius (checked, do not overstate):** `pitch_recommender.py:48-52` reads
  `completeness_score` into a local that is **never referenced again** — dead code — so the stale
  value does not affect `recommended_service`. The damage is confined to the stale export.
- **Fix:** add `r["completeness_score"] = completeness_score(r)` as step 1, matching
  `037-cli-design.md:303`, and delete the dead local at `pitch_recommender.py:48-52`.

### S3 — Three exit-code and flag contracts from `037-cli-design.md` are unmet

- **`037:281`** says exit `2` = *"Input file missing **or unreadable**"*. `cli.py:255` only checks
  `path.exists()`, so a `chmod 000` file raises `PermissionError` (traceback, exit 1) and a
  directory raises `IsADirectoryError` (traceback, exit 1). Verified both.
- **`cli.py:254` + `Path("")`.** `leadminer score ""` → `pathlib.Path("")` is `Path(".")`, and
  `Path(".").exists()` is `True`, so the guard at `:255` passes and `open(".")` raises
  `IsADirectoryError: '.'`. Verified.
- **`037:298-299`** specifies `--min-lead-score` and `--min-completeness`. Neither exists
  (`cli.py:304-307` declares only the positional `file` and `--out`). These two filters are the
  only mechanism the design offers for shrinking the set before a pitch campaign.
- **Fix:** `if not path.is_file(): return 2`; reject a blank `args.file`; add the two flags.

### S3 — `cmd_score` scores on `website_live` data it never refreshes

- **Where:** `cli.py:265-272` calls `check_websites` nowhere, yet `lead_score`
  (`enricher.py:300-304`) and `recommend_service` (`pitch_recommender.py:34-36,57,70,73`) both
  branch on it, for up to **30** points of lead_score.
- **Breaks:** correct behaviour by design (the docstring at `cli.py:248` and `:12` promise no
  network), but it means `score` can silently re-weight an entire master on liveness verdicts
  that are months old. Nothing in the output records the staleness, and `scraped_at` is left
  untouched so the row still looks freshly crawled.
- **Fix:** add `--refresh-websites` (opt-in, network) and, in the default offline mode, print how
  old the `website_live` verdicts are, or null them out beyond a TTL so stale verdicts stop
  scoring.

### Not bugs — verified, do not "fix" these

- **`write_csv` leaves no temp file** on any of the seven crash paths I exercised
  (`main.py:131-133` works).
- **`cmd_score` makes no network calls**, confirmed with a `requests` stub that raises on contact.
- **`stats`, `validate`, `doctor` stay import-clean** with `requests` absent, because `cli.py:18-24`
  imports only stdlib at module level. That property is fragile and worth a test
  (`238-x.md:308-312` says the same) — but it is currently true, and the lazy imports at
  `cli.py:249-252` are load-bearing.
- **Arabic, French-accented, emoji, NFD-combining-mark and whitespace-heavy names all
  round-trip byte-exact.** `utf-8-sig` on both read (`main.py:85`) and write (`main.py:124`) is
  correct and the BOM cannot glue itself to `name`.
- **Emoji in a phone number** yields `"961"` after `re.sub(r"\D","")` and is correctly rejected by
  the `>= 7` gate at `enricher.py:292`. No hardening needed.
- **A 2-column CSV** does not crash; it produces 20 blank columns and a `lead_score` computed from
  an empty record. Ugly, not dangerous.
- **Duplicate header names** are handled by DictReader (last wins). Only worth a header validator.

### S3-1 — `leadminer score` is documented as offline but cannot start without the HTTP stack

- **Where:** `cli.py:249` (`import main as pipeline`) → `main.py:25` → `scrapers/osm.py:4` →

  entirely dead and as "the sole `requests`-adjacent reason `cmd_score` pulls in `enricher`".
  Cross-reference: this is already reported at `238-x.md:313-317`.

## The single most dangerous input

**A master CSV whose header contains any column outside `main.FIELDS`** — which is the normal
state of `data/all_businesses.csv` after a sales rep adds `notes`/`owner`/`stage` in Google
Sheets and that file round-trips through `scrape.yml:56` and `:89`.

Every other hostile input in the matrix is loud. The `inf` cell, the 128 KiB field, the
directory argument and the `.gz` file all produce a Python traceback; the operator sees it,
nothing is written, and they try something else. The extra-column input produces **exit code 0
and a line that reads "re-scored 12,431 records, 3,102 changed"** — and the sales notes,
ownership and pipeline-stage columns are gone from the file. Nobody discovers this for weeks,
because:

1. **It happens on the default path.** `--out` is optional (`cli.py:274`); the design doc's own
   worked example is an in-place re-score (`037-cli-design.md:493`).
2. **It is permanent.** `data/` is gitignored (`.gitignore:5`) and `write_csv` takes no snapshot.
   The only recovery is a hand-picked Drive folder from `scrape.yml:88`.
3. **It is amplified by the workflow.** The next weekly run uploads the column-less master back
   over `gdrive:leads/` (`scrape.yml:89`), so the loss propagates to the shared sales folder and
   to every rep who has the file open.
4. **It is most likely exactly when you would run `score`** — right after a scoring-rule change,
   which is the moment a new column exists — and right after someone has been working in the file.
5. **The success message misdirects.** `"N changed"` counts only `lead_score` (S2 above), so the
   operator is told the delta was small while a whole column evaporated.

The `country`/`region` contradiction (S2) is the most *widespread* silent corruption — it hits
every row with a blank `country` cell — but it is at least detectable afterwards by cross-checking
`country` against `lat`/`lon`, and `main.py:184` already does the same thing during a normal run,
so it is a `resolve_country` problem rather than a `cmd_score` problem. The extra-column loss is
unique to the command that writes by default.

## Not a bug, but worth knowing

- **Concurrent `leadminer score` runs corrupt each other.** `main.py:122` derives the temp path as
  `path.with_suffix(path.suffix + ".tmp")` — deterministic, no PID, no `O_EXCL`. Two processes
  scoring the same file write the same `all_businesses.csv.tmp`; the second `os.replace` publishes
  a file whose tail came from the first process's buffer. `scrape.yml:15-17` guards the *workflow*
  with a concurrency group, but nothing guards two local shells. `051-atomic-writes-and-concurrency.md:100-102`
  already prescribes `fcntl.flock`; it is simply not implemented.
- **A symlinked master is silently converted to a regular file** by an in-place `score`
  (`main.py:130`). Verified: `link.is_symlink()` is `False` after the run. Relevant if anyone ever
  points `data/` at a synced folder.
- **`cmd_score` does not re-normalize `phone`**, unlike `main.py:192-194`. `210-x.md:123-126`
  already found the resulting divergence (`run` → `+966501234567`, `cmd_score` → `00966501234567`).
  Impact here is low because `enricher.py:285` strips non-digits anyway.
- **Concurrent-agent debris in the repo root.** Three stray files named `" "`, `-` and `0` exist at
  the repo root, each a 374-byte UTF-8-BOM CSV containing `Cafe Beirut,restaurant,Beirut,LB,…`.
  They are not from this audit (my fixtures use different data) — they are shell-redirection
  debris from another agent probing `cmd_score` concurrently. I left them untouched per the
  one-file rule, but whoever tidies the tree should know they are test output, not data.
- **The design doc and the implementation disagree on flags**: `037:296-297` specifies
  `-i/--input` and `-o/--output`; the implementation uses a positional `file` plus `--out`. The
  `--out` default change (new file → in-place) is the consequential part; see S1.

## Recommended order of work

1. **Make `cmd_score` non-destructive by default** — require `--out`, or default to
   `path.with_suffix(".rescored.csv")`; add `--dry-run`; take a `.bak` before the first destructive
   write; validate the input header against `FIELDS` and refuse to run on a mismatch (S1).
2. **Make `load_master` total** — `except (ValueError, TypeError, OverflowError)` or a
   `_to_int` helper using `math.isfinite`; `csv.field_size_limit(2**20)`; catch `_csv.Error` per
   row. This one change fixes both crash findings *and* de-fangs the weekly run (S1-1, S2-4).
3. **Fix the reporting** — per-field delta counts; say explicitly that the file is always
   rewritten; name the four sibling exports that are now stale (S2-2, S2-3).
4. **Stop `cmd_score` from inventing `country`** — or re-run `infer_region` with it and refuse to
   write on disagreement; record `country_source` (S2-1).
5. **Sweep the schema checks against `037-cli-design.md`** — add
   `completeness_score` recomputation, `is_file()` for exit 2, and the two `--min-*` flags (S3).
6. **Break the `main` → `scrapers` → `httpclient` → `requests` import chain** for the offline
   commands by extracting `load_master`/`resolve_country`/`write_csv` into a stdlib-only module
   (S3-1).
7. **Add `fcntl.flock` on `data/.leadminer.lock`** around every `cmd_*` that writes, and make the
   temp name unique (`tempfile.mkstemp` in the target directory) so two concurrent runs cannot
   share a buffer.
8. **Tests.** None of the 40 rows in the matrix above are covered — `tests/` contains one file,
   `test_lead_signal.py`. A single parametrized table over (cell value × expected outcome) against
   `cmd_score` would have caught items 1-4 outright.
