# 248 — `cmd_score` (cli.py:247) input/output audit

## Verdict

`cmd_score` is **not a re-scorer, it is an in-place rewriter of four columns with
no dry run, no backup, and a change counter that only watches one of them.** Three
things go wrong that block trust in the output: it silently deletes every column
outside the 22-field schema (S1-1), it stamps an unrecoverable guess into
`country` (S1-2), and it rewrites `industry_priority` without rebuilding the four
derived CSVs that are defined *by* that column — so `sales_ready.csv` ends up
contradicting `all_businesses.csv` in the same commit (S1-3).

What it gets right: it is genuinely network-free, and it **is** idempotent from the
second run onward (verified: three consecutive runs produced byte-identical
`sha256 a554aef8ca4e4b36…`). Both of those are stated precisely under
"Not a bug, but worth knowing" — including the invariant that makes it idempotent,
which is the same invariant that makes S1-2 irreversible.

**Callers.** `cmd_score` has exactly one dispatch site, `cli.py:307`
(`set_defaults(func=cmd_score)`), reached through `main()` at `cli.py:315`. Nothing
else in the repo calls it (verified by grep for `cmd_score`). So "every caller" is
`main()` plus the `argparse` default at `cli.py:305`, which points `file` at
`data/all_businesses.csv` **relative to CWD** (`DATA_DIR = pathlib.Path("data")`,
`cli.py:26`), and leaves `--out` unset (`cli.py:306`) — i.e. the zero-argument form
`leadminer score` is the maximally destructive one.

**How the findings below were produced.** `requests` is not installed in this
checkout, which is itself finding **S2-4**. To execute the function I put a
read-only stub package on `sys.path` in a scratch directory
(`/private/var/folders/…/T/opencode/lm248/stubs/requests/__init__.py`) — no
`pip install`, no repository file touched, no network. `main`'s import graph needs
`requests` and nothing else (`grep` over `scrapers/*.py`: only
`google_places.py:24` imports it at module scope; `bs4`/`lxml` are not imported
anywhere). Every "BEFORE/AFTER" pair below is real stdout from that harness.

## Findings

### S1-1 — `leadminer score` silently deletes every column that is not one of the 22 fields, in place

- **Where:** `cli.py:275` (`pipeline.write_csv(out, records)`) →
  `main.py:125` `csv.DictWriter(f, fieldnames=FIELDS, extrasaction="ignore")`
- **Breaks:** `load_master` (`main.py:85`) reads whatever header the file has, but
  `write_csv` writes `FIELDS` and silently drops everything else. Because
  `cli.py:274` defaults `out` to the input `path`, the default invocation
  overwrites the source file with 22 columns. The master is explicitly *built for
  humans* — `write_csv` uses `utf-8-sig` with the comment "so Excel and Google
  Sheets detect UTF-8" (`main.py:118-119`) — so a `notes`, `sales_owner` or
  `last_contacted` column added by a human is the expected case, not an edge case.
  Exit code is `0`; nothing is printed about the loss.
- **Trigger** (executed): a 1-row CSV with header
  `…scraped_at,notes,sales_owner,last_contacted` and those three cells populated.
  `cli.main(["score", "<file>"])`:
  ```
  BEFORE HEADER: …,scraped_at,notes,sales_owner,last_contacted
  BEFORE ROW   : …,2026-01-01T00:00:00+00:00,value-0,value-1,value-2
  re-scored 1 records, 1 changed -> …/extras.csv      exit: 0
  AFTER  HEADER: …,scraped_at
  AFTER  ROW   : …,2026-01-01T00:00:00+00:00
  >>> columns lost: ['notes', 'sales_owner', 'last_contacted']
  ```
  The same mechanism accepts a file that is not a leadminer export at all. A plain
  contact list `full_name,email,notes / Jane Doe,jane@x.com,call tuesday` becomes,
  in place, a 23-column leadminer file with `name=""`, a fabricated
  `lead_score=20` and `recommended_service="Full digital launch (brand + website +
  social setup)"`, exit `0`. There is no schema check anywhere in `cmd_score`.
- **Fix:** one line — derive the output header from the input header instead of the
  constant: `fieldnames = list(records[0].keys())` union `FIELDS`
  (`main.py:125`), and refuse to write in place unless `--in-place` is passed.

### S1-2 — `country` is overwritten with `resolve_country`'s fallback, and the fallback is then permanent

- **Where:** `cli.py:266` `r["country"] = pipeline.resolve_country(r)`;
  the decision is `main.py:59-74`
- **Breaks:** `resolve_country` accepts `LB/SA/LEB/LBN/KSA/SAU/SAU-AR` and treats
  everything else as unknown, then falls back to a phone-prefix sniff and finally to
  `_DEFAULT_COUNTRY = "LB"` (`main.py:47`, `main.py:74`). `cmd_score` writes that
  verdict into the cumulative master. Because `resolve_country` short-circuits on
  **any** non-blank value (`main.py:59-67`), the guess is thereafter indistinguishable
  from ground truth — `main()` (`main.py:184`) and every future `score` will keep it.
  A Saudi lead is permanently stamped `LB`, which then drives
  `enricher.infer_region`'s box selection (`enricher.py:90`: `_KSA_COORD_REGIONS` vs
  `_LB_COORD_REGIONS`) and every by-region report built off it.
- **Trigger** (executed), two distinct inputs on a 7-row fixture:
  | `country` in | `phone` | truth | `country` out | |
  |---|---|---|---|---|
  | `"Saudi Arabia"` | *(none)* | SA | **`"LB"`** | wrong |
  | `""` | `"+971501234567"` | UAE | `"LB"` | wrong by default |
  | `""` | `"+966501234567"` | SA | `"SA"` | ok |
  ```
  file now says: ['SA', 'LB', 'LB', 'SA', 'SA', 'SA', 'LB']
  resolve_country({"country": "LB", "phone": "+966501234567"}) -> 'LB'   # sticky
  ```
  Note the `"Saudi Arabia"` row: the record *states* its country in plain English
  and `cmd_score` still overwrites it with `LB` because there is no phone to
  disambiguate with. A `+971` phone is not hypothetical — `dedup.py:8-21` lists UAE,
  Jordan, Kuwait etc. as codes the pipeline deliberately handles because
  "data leaks across borders constantly".
- **Fix:** only assign when the cell is blank *and* the phone yields an unambiguous
  prefix, i.e. `new = resolve_country(r); r["country"] = new if new != _DEFAULT_COUNTRY or r.get("country") else r.get("country")` —
  or, cleaner, make `resolve_country` return `str | None` and have `cmd_score` leave
  the cell untouched on `None`.

### S1-3 — `industry_priority` is rewritten but the four CSVs derived from it are not, so the exports contradict each other

- **Where:** `cli.py:267` rewrites `industry_priority`; `cli.py:274-275` writes
  exactly one file. The subsets are produced **only** in `main.py:199-213`, and
  `sales_ready.csv` is *defined* by that column at `main.py:202-205`
  (`industry_priority in ("high", "medium")`).
- **Breaks:** after `leadminer score`, `all_businesses.csv` and `sales_ready.csv`
  disagree, are written by the same command on the same day, and carry no marker.
  `sales_ready.csv` is the handoff artefact — `pitch_recommender.py:7` says
  `recommended_service` is "a starting hypothesis on the first outbound message",
  and `main.py:226` prints it as "SALES-READY (actionable)". A salesperson working
  the list is working a membership rule that the master no longer agrees with.
- **Trigger** (executed): 2 rows in `data/all_businesses.csv`, both currently
  `industry_priority=high`, both present in `data/sales_ready.csv`. Row 2's
  `category` is `"dental clinic"` (with a space) — `whitelist.industry_priority`
  (`whitelist.py:141-145`) is an exact set membership, so it does not match
  `PRIORITY_INDUSTRIES`' `"dental_clinic"` and returns `"low"`:
  ```
  BEFORE master   : [('Row1','high','30'), ('Row2','high','30')]
  BEFORE sales_rdy: [('Row1','high'), ('Row2','high')]
  re-scored 2 records, 1 changed   exit: 0
  AFTER  master   : [('Row1','high','30'), ('Row2','low','15')]
  AFTER  sales_rdy: [('Row1','high'), ('Row2','high')]
  >>> sales_ready still contains a row the master classifies as 'low': True
  ```
  The failure is symmetric: a whitelist fix that promotes a category upgrades
  `industry_priority` in the master while the row stays *missing* from
  `sales_ready.csv` until the next full `run`.
- **Fix:** have `cmd_score` write the master and then re-derive the four subsets
  with the same predicates as `main.py:199-206` (extract them into one
  `partition(records) -> dict[str, list[dict]]` used by both), or rename the command
  so it does not read as a full re-score.

### S2-1 — the `changed` counter only measures `lead_score`, so a run that rewrote the whole file can print `0 changed`

- **Where:** `cli.py:270-271` `if new != r.get("lead_score"): changed += 1`
- **Breaks:** the loop writes four columns — `country` (`cli.py:266`),
  `industry_priority` (`cli.py:267`), `recommended_service` (`cli.py:268`) and
  `lead_score` (`cli.py:272`) — but only the last is diffed. `lead_score` does not
  read `country` at all (`enricher.py:283-319`), so every blank-`country` row is
  rewritten and none are counted. The operator's only signal about how much the
  command did is wrong, and it is wrong in the direction that says "nothing
  happened".
- **Trigger** (executed): 1 row, fully current for every scoring rule
  (`lead_score=30`, `industry_priority=high`), `country` blank:
  ```
  BEFORE: [('Cafe A', '', '30')]
  re-scored 1 records, 0 changed -> …/data/all_businesses.csv     exit: 0
  AFTER : [('Cafe A', 'LB', '30')]
  ```
  The file changed and the tool reported `0 changed`.
- **Fix:** diff all four written columns and print a per-column breakdown:
  `changed = sum(1 for r in records if r != before[i])`, plus a
  `collections.Counter` of which fields moved.

### S2-2 — `completeness_score` is the one derived column `cmd_score` never recomputes

- **Where:** `cli.py:266-272` — the loop refreshes `country`, `industry_priority`,
  `recommended_service`, `lead_score` and skips `completeness_score`, which
  `enrich()` sets at `enricher.py:349` (and `cmd_score` never calls `enrich`).
- **Breaks:** `enricher.completeness_score` (`enricher.py:101-117`) is a pure
  function of five fields with no I/O — there is no reason it cannot be refreshed
  offline. Its staleness is not cosmetic: `qualified_businesses.csv` is defined as
  `completeness_score >= 1` (`main.py:206`), so a blank cell silently removes the
  row from a product file while `cmd_score` reports success.
- **Trigger** (executed): one row with `phone`, `address` and `email` populated and
  `completeness_score=""`:
  ```
  BEFORE completeness_score: ''   (should be 3)
  re-scored 1 records, 1 changed      exit: 0
  AFTER  completeness_score: ''   lead_score: 50
  enricher.completeness_score(row) -> 3
  ```
  The row was simultaneously reported as "changed" and left wrong.
- **Fix:** `r["completeness_score"] = completeness_score(r)` in the loop
  (`from enricher import completeness_score` at `cli.py:250`).

### S2-3 — `recommended_service` is re-derived from a liveness verdict that was never re-checked, with no staleness marker

- **Where:** `cli.py:268`; consumed at `pitch_recommender.py:34-36` and
  `pitch_recommender.py:55-58`
- **Breaks:** `recommend_service` keys its strongest branch off
  `website_live is False` (`pitch_recommender.py:55-58`, "the strongest pitch in
  the database"). `cmd_score` re-derives the recommendation from whatever
  `website_live` string is in the CSV, which is a snapshot taken on `scraped_at` —
  a field present in every record and read by nobody in `cmd_score`. A lead whose
  site died between runs keeps the weakest possible branch forever.
- **Trigger** (executed): `scraped_at=2025-11-02T09:00:00+00:00`,
  `website=https://oldsalon.example`, `website_live=True`, `rating=4.6`,
  `review_count=52`, `category=beauty`:
  ```
  AFTER : website_live=True recommended_service='Discovery call - scope the right service'
  same row with website_live=False would pitch: 'Website rebuild + maintenance'
  ```
  Nine of the recommender's tiers are skipped before the row lands on the
  `pitch_recommender.py:98-99` fallback, while the one pitch the sales team most
  wants is available and unreachable.
- **Fix:** read `scraped_at` in the loop and either (a) skip `recommended_service`
  for rows older than a threshold, or (b) print the median and max record age in the
  `cli.py:276` summary so the operator sees the pitch is derived from stale probes.

### S2-4 — the one "no network" command that needs the full scraper import graph dies with a raw traceback

- **Where:** `cli.py:249` `import main as pipeline`
- **Breaks:** `main.py:25-27` imports all three scrapers; `scrapers/osm.py:4` →
  `httpclient.py:43` → `requests`. `cli.py:14-15` and `cli.py:248` both promise this
  command is network-free and "safe to run anywhere", and `cmd_stats` /
  `cmd_validate` (`cli.py:79`, `cli.py:135`) honour that by importing nothing at
  all. `cmd_doctor` guards exactly this failure at `cli.py:226-231` ("doctor exists
  to diagnose a broken environment, so it must never be the thing that tracebacks").
  `cmd_score` does not, and `cli.py:316` only catches `KeyboardInterrupt`.
- **Trigger** (executed, no stub on `sys.path`, real file present):
  ```
  cli.main(['score', '/tmp/.../all_businesses.csv'])
  Traceback (most recent call last):
    File "cli.py", line 315, in main
      return int(args.func(args) or 0)
    File "cli.py", line 249, in cmd_score
      import main as pipeline
    File "main.py", line 25, in <module>
      from scrapers.osm import OSMScraper
    File "httpclient.py", line 43, in <module>
      import requests
  ModuleNotFoundError: No module named 'requests'
  ```
  `leadminer doctor` would have told the user the fix; `leadminer score` hands them
  a stack trace instead, for the one command they reach for when a run looks wrong.
- **Fix:** wrap `cli.py:249-252` in `try: … except ImportError as e: print(f"  FAIL  missing dependency: {e.name} — run: pip install -e '.[dev]'", file=sys.stderr); return 1`.

### S3-1 — `website_live` is coerced from the exact literals `"True"`/`"False"`; anything else is blanked, in place

- **Where:** `main.py:102-103`, reached from `cli.py:259`; the value is then
  written back at `cli.py:275`
- **Breaks:** any other spelling is silently mapped to `None` = "we never got an
  answer" (`enricher.py:154-156`). The cells are then overwritten with an empty
  string, so the original text is gone. A hand-edit or any third-party CSV export
  ("true", "TRUE", "1", "yes") loses the +10 live bonus at `enricher.py:301-302`
  and moves the pitch off the live branch entirely. The same literal comparison is
  duplicated in `cmd_stats` at `cli.py:107-108`, so the CLI and the CSV reader
  agree with each other and both are brittle.
- **Trigger** (executed): a row with `website_live="true"`:
  ```
  before website_live: 'true'
  re-scored 1 records, 1 changed      exit: 0
  after  website_live: ''
  ```
  `lead_score` went `45 → 30` and `recommended_service` changed with it.
- **Fix:** parse tolerantly in one place — in `load_master`, map
  `{"true","t","1","yes","y"} → True`, `{"false","f","0","no","n"} → False`
  (case-insensitively) — and have `cmd_stats` call that instead of re-comparing.

### S3-2 — the safe path is the opt-in path

- **Where:** `cli.py:274` `out = pathlib.Path(args.out) if args.out else path`
- **Breaks:** `--out` is optional and `--in-place` does not exist, so
  `leadminer score` with no arguments destroys-and-replaces the cumulative master
  (combined with S1-1 and S1-2, irreversibly). There is no `--dry-run`. The
  behaviour is correct — `--out` does work, including into a directory that does not
  exist yet (`write_csv` mkdirs parents at `main.py:121`; verified, exit `0`, input
  left untouched) — it is just the wrong default for a command whose failure modes
  are silent.
- **Fix:** make `--out` required unless `--in-place` is passed, and have
  `--dry-run` print the `changed`/`would-change` summary without writing.

## Not a bug, but worth knowing

- **`cmd_score` is idempotent, and here is the invariant that guarantees it.**
  The four written columns are pure functions of fields `cmd_score` never mutates:
  `resolve_country` reads `country`/`phone` (`main.py:59-72`),
  `industry_priority` reads `category` (`whitelist.py:133-145`),
  `recommend_service` reads `website`/`website_live`/`category`/`rating`/
  `review_count`/`social` (`pitch_recommender.py:31-53`) — none of which is
  `lead_score` or `industry_priority` — and `lead_score` reads `industry_priority`,
  which is set from the unchanged `category` (`enricher.py:306-310`). So after run
  *N* the record is a fixed point of all four functions. Verified: three consecutive
  runs → `sha256` prefixes `a554aef8ca4e4b36` × 3. **Caveat:** the same
  short-circuit at `main.py:59-67` that makes this invariant hold is exactly what
  makes S1-2 irreversible. The idempotency is bought with a lie already told.
- **`score` output is not `run` output.** `cmd_score` does not dedup, does not
  re-apply `is_business_category`, does not call `enrich()` (no liveness refresh, no
  contact extraction, no `completeness_score`), and does not re-run
  `normalize_phone` (`main.py:194`). That is the correct reading of "no network",
  but it means `leadminer score` cannot be used to preview what `leadminer run`
  would produce, and it cannot recover a stale `website_live` (S2-3).
- **Degenerate inputs are handled cleanly.** Header-only CSV → exit `1`,
  `"has no usable rows"` (`cli.py:260-262`). 0-byte file → also exit `1`; note it
  is not distinguished from "empty CSV", and the path existence check at
  `cli.py:255` passes for a 0-byte file, so the message is slightly misleading.
- **Ragged rows are silently truncated.** A row with more cells than the header
  lands in `DictReader`'s `None` restkey and is dropped by
  `extrasaction="ignore"`. Exit `0`, no warning.
- **`lead_score` saturates.** Components sum to 110 and `min(score, 100)`
  (`enricher.py:319`) clamps, so the best leads are indistinguishable at 100 —
  `cmd_score` cannot rank the top of the list. Out of this lens; relevant to anyone
  using the command's output for prioritisation.

## Recommended order of work

1. **S1-1** — one line in `main.py:125` (derive `fieldnames` from the input header)
   plus a schema check in `cmd_score`. Do this first: it is the cheapest change and
   it is the only one that destroys human data.
2. **S1-2** — gate `cli.py:266` on a genuinely derived country. Two lines; removes
   the only *irreversible* corruption in the function.
3. **S1-3** — extract `main.py:199-206` into `partition(records)` and call it from
   `cmd_score` too, so the four exports can never disagree with the master.
4. **S3-2** + **S2-1** — invert the default (`--out` required, `--in-place` opt-in,
   `--dry-run`) and make the summary line report per-column movement. Together these
   are what would have made S1-1 and S2-1 visible instead of silent.
5. **S2-2** — one line (`completeness_score` is pure and offline).
6. **S2-4** — `try/except ImportError` around `cli.py:249-252`, mirroring
   `cli.py:226-231`.
7. **S2-3** — surface record age from `scraped_at` in the summary; decide
   separately whether `score` should re-derive `recommended_service` at all for
   stale rows.
8. **S3-1** — tolerant tri-state parse in `load_master`, shared with `cmd_stats`.
