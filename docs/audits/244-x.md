# 244 — `cmd_doctor` (cli.py:204): declared contract vs. actual contract

## Verdict

`cmd_doctor` cannot fail for the reason it exists. Its exit code ignores all three
connectivity results (`ok` is cleared only by the *presence* of `GOOGLE_PLACES_API_KEY`,
cli.py:208-214), and its Google Places probe is a `GET` against a POST-only endpoint
with the API key omitted and a `< 500` pass threshold — so 401/403/404/405/429 all print
`OK` with an empty note. The result is a diagnostic that returns exit 0, and prints
green, in precisely the situations that produce a zero-record run.

The lens premise does not hold: **`cmd_doctor` reads and writes zero `BusinessRecord`
fields.** It never touches `scrapers/base.py`. The record-shaped boundary in this CLI is
`csv.DictReader` at cli.py:87 and cli.py:143, and the declared/actual mismatch there is
real but is suppressed by a `# type: ignore` at cli.py:167. Details in
"Fields read/written outside the TypedDict" below.

## Contract: declared vs. actual

| | Declared | Actual | Verdict |
|---|---|---|---|
| Input | `args: argparse.Namespace` (cli.py:204) | **Nothing.** `args` is never dereferenced anywhere in cli.py:204-244. The `doctor` subparser (cli.py:301-302) registers zero `add_argument` calls, so the Namespace it builds holds only `cmd="doctor"` and `func=<cmd_doctor>`. | Annotation admits literally any Namespace. It is satisfiable by anything and violated by nothing — it does zero work. Contrast `cmd_stats:81` / `cmd_score:254`, which read `args.file` against the same unannotated type: those have an *undeclared* contract enforced only by an `AttributeError` at runtime. |
| Return | `int` (cli.py:204) | `Literal[0, 1]`. Two return statements: `return 1` (cli.py:231, `requests` not installed) and `return 0 if ok else 1` (cli.py:244). | Correct and safely wider than reality. No consumer needs a 3rd value today — but see S1-1. |
| Side effects | none declared | 3 sequential `requests.get` (cli.py:239), 2 env reads (cli.py:211), 1 directory glob (cli.py:219) | Under-documented; the module docstring's "commands other than run/scrape/doctor never touch the network" (cli.py:14) correctly excludes it, but the README's `leadminer doctor  # check keys and connectivity first` (README.md:95) reads as free. |

**Can any caller violate the contract silently?** For `cmd_doctor`: no, and that is the
problem — there is no contract to violate in either direction. `args` is ignored, the
return is a closed `{0, 1}` set, and nothing mutates `DATA_DIR`. It cannot be called
wrong. It can only be *called right and be wrong*, which is S1-1 and S1-2.

**Where its return value is consumed, and how each site fails on an unexpected shape:**

1. `cli.py:315` — `return int(args.func(args) or 0)`. The only consumer.
   - `or 0` silently maps any falsy return (`None`, `False`, `0`, `""`) to `0`. Verified:
     `int(lambda: None() or 0)` → `0`. See S1-3 for the live instance of this.
   - `int(...)` raises `ValueError`/`TypeError` on any *truthy* non-int, and `main()`
     catches only `KeyboardInterrupt` (cli.py:316), so the traceback escapes. Verified:
     `int(lambda: 'WARN' or 0)` → `ValueError: invalid literal for int() with base 10`.
     Unreachable from `cmd_doctor` (it returns real ints) but reachable from any handler
     that returns a non-int.
2. `cli.py:322` — `raise SystemExit(main())`. Correct for an int; masks any value >255 at
   the OS boundary. Not reachable today.
3. `pyproject.toml:33` — `leadminer = "cli:main"`. The console-script wrapper does its own
   `sys.exit()`, so it would tolerate a non-int (`sys.exit("WARN")` prints the string and
   exits 1). Masked by the `int()` at cli.py:315 raising first.
4. Shell / CI. `scrape.yml` has **no** `doctor` step (verified, file is 98 lines: install →
   rclone → `python main.py` → row-count guard → upload). README.md:95 only tells humans.
   So a `leadminer doctor && leadminer run` chain is a no-op today, and adding one would
   still be a no-op until S1-1 is fixed.

## Findings

### S1-1 — Every connectivity result is discarded; doctor exits 0 with all three FAIL

- **Where:** `cli.py:208` (`ok = True`), `cli.py:213-214` (the only place `ok` is
  cleared), `cli.py:233-243` (the loop that never touches `ok`), `cli.py:244`.
- **Breaks:** `ok` is set to `False` only when `GOOGLE_PLACES_API_KEY` is *absent*. Three
  `FAIL` lines — the exact output of a machine with no DNS, a blocked egress, or a proxy
  that blackholes the three hosts — are followed by `return 0`. A doctor's green exit is
  its entire product; this one is decorative. `docs/audits/037-cli-design.md:433`
  specified "Runs `doctor` pre-flight checks. Aborts immediately on exit code `3` or `4`
  before any network queries are initiated" — neither the abort nor the codes exist.
- **Trigger:**
  ```
  $ cd /Users/mhomsi/dev/dummy/leadminer
  $ GOOGLE_PLACES_API_KEY=dummy leadminer doctor; echo "exit=$?"
  credentials:
    OK   GOOGLE_PLACES_API_KEY
    MISSING  SCRAPER_EMAIL
  data directory:
    MISSING  data (no run has produced output yet)
  connectivity (5s timeout each):
    FAIL  Overpass       ConnectionError
    FAIL  Wikidata       ProxyError
    FAIL  Google Places  ConnectionError
  exit=0
  ```
  Same output, `exit=0`, on a laptop in aeroplane mode with the key exported.
- **Severity defence:** S1 because it is a wrong result presented as a passing check, and
  because the human or script consuming it is explicitly told to trust it
  (README.md:95, cli.py:205 docstring "before blaming the data").
- **Fix:** track a `failures` list; `ok = not problems`, where a connectivity `FAIL` or a
  `WARN` both append, and return `3` for credential/config failures and `4` for
  connectivity (037's vocabulary).

### S1-2 — The Google Places probe is a GET to a POST-only endpoint, sends no key, and `< 500` means auth failures print `OK`

- **Where:** `cli.py:236` (URL), `cli.py:239` (`requests.get`), `cli.py:240-241`
  (`r.status_code < 500`).
- **Breaks:** three independent defects stacked in four lines.
  1. **Wrong verb.** Google's docs: "A Text Search (New) request is an HTTP **POST**
     request of the following form: `https://places.googleapis.com/v1/places:searchText`"
     (https://developers.google.com/maps/documentation/places/web-service/text-search).
     `scrapers/google_places.py:227` correctly uses `session.post(API_URL, json=body, …)`.
     A `GET` on a known path returns a 4xx (404/405), which is under the threshold.
  2. **No credential in the request.** The scraper sets `X-Goog-Api-Key` at
     `google_places.py:161-165`; doctor's bare `requests.get` sends nothing. **No response
     this probe can produce is evidence about the key.** A revoked, quota-exhausted,
     billing-disabled, or Places-API-not-enabled key all pass.
  3. **The threshold inverts the meaning of the check.** `401` (unauthenticated), `403`
     (API restricted / key invalid — the code Google returns for a key without the Places
     API enabled), `404`/`405` (wrong verb), `429` (rate limited) are all `< 500`, so they
     print `OK` with an empty `note` — the most misleading possible line, green with no
     detail. For Overpass this is not hypothetical: the OSM wiki documents 429 and 406 as
     real `overpass-api.de` responses ("If you receive an HTTP error code such as 429 or
     406, pause for 30 seconds", https://wiki.openstreetmap.org/wiki/Overpass_API).
     Wikidata returns 403 for User-Agent policy violations (see S3-4) — also `< 500`.
  Net effect: the one credential the pipeline hard-depends on is checked for *presence
  only*, and the network check cannot distinguish "reachable" from "reachable and
  rejecting me".
- **Trigger:** set `GOOGLE_PLACES_API_KEY` to a syntactically valid but disabled key (the
  single most common misconfiguration — README.md:90 tells you to enable Places API (New)
  in the console, implying you might forget). `leadminer doctor` prints
  `OK   GOOGLE_PLACES_API_KEY` and `OK   Google Places`. The actual run then prints
  `[Google] FATAL: invalid API key (401)` from `google_places.py:231` — or, since that
  branch only matches `401` and Google's key failures surface as 403, falls through to
  `resp.raise_for_status()` at `google_places.py:249` → `RequestException` at
  `google_places.py:250` → `[Google] Request error for 'restaurants in Lebanon': ...`
  for all 68 queries, and the run publishes whatever OSM+Wikidata produced.
- **Fix:** `ok = 200 <= status < 300`, and probe Google with a real POST
  (`json={"textQuery": "x", "maxResultCount": 1}`, `X-Goog-FieldMask: places.id`,
  `X-Goog-Api-Key` from the env) so 401/403 are FAIL. Note the POST probe consumes one
  billable request; if that is unacceptable, validate the key against a non-billable
  Google endpoint and say so in the output.

### S1-3 — `int(args.func(args) or 0)` launders a missing return into exit 0, and `cmd_run` already returns `None`

- **Where:** `cli.py:315`; the live violation is `cli.py:37`
  (`return pipeline.main()`) against `main.py:148` (`def main() -> None`).
- **Breaks:** `cmd_run` is declared `-> int` and returns `None` on its only successful
  path. `int(None or 0)` → `0`. So `leadminer run` exits 0 unconditionally on any
  non-raising path. This matters because `main.main()` swallows every scraper exception at
  `main.py:167-168` (`except Exception as e: print(... ERROR ...)`) and continues with an
  empty `raw` list. A run where all three sources fail completely exits **0** and writes
  five CSVs; locally there is no row-count guard, only the one in `scrape.yml:78-83`.
- **Trigger:**
  ```
  $ cd /Users/mhomsi/dev/dummy/leadminer
  $ GOOGLE_PLACES_API_KEY= HTTPS_PROXY=http://127.0.0.1:9 leadminer run 2>&1 | tail -3
  [OSM] FAILED after 3 attempts: ... Continuing without OSM data.
  [Wikidata] FAILED after 3 attempts: ... Continuing without Wikidata data.
  Total raw records from scrapers: 0
  $ echo "exit=${PIPESTATUS[0]}"   # 0
  ```
  And the generic form of the trap — any future handler that forgets its `return` exits 0
  with no output:
  ```python
  # hypothetical handler in the same dispatch table
  def cmd_export(args): print("exporting")   # no return
  # -> int(args.func(args) or 0) -> exit 0. Verified.
  ```
- **Severity defence:** S1 because a total source failure is a wrong result reported as
  success. It sits on my target's only call path (`cli.py:315` is the single consumer of
  *every* `cmd_*` return, `cmd_doctor` included), so it is in scope for this lens.
- **Fix:** delete the `or 0` (it exists only to tolerate `None`, which is the bug);
  change `main.main()` to return `int` and return non-zero when `raw_filtered` is empty or
  when any scraper reported `ERROR:`; widen the `except` at `cli.py:316` to
  `(KeyboardInterrupt, SystemExit)` is *not* wanted — instead let real exceptions
  propagate as exit 1.

### S2-1 — `DATA_DIR` is cwd-relative, so the data section inspects the wrong directory, and `doctor` never opens a CSV

- **Where:** `cli.py:26` (`DATA_DIR = pathlib.Path("data")`), used at `cli.py:217` and
  `cli.py:219`; the pipeline's own copy is `main.py:41`.
- **Breaks:** three distinct lies, all in the seven lines an operator reads to decide
  whether their data is intact.
  1. **Wrong directory.** `DATA_DIR` resolves against the process cwd. From anywhere but
     the repo root, doctor reports `MISSING  data (no run has produced output yet)` —
     "no run has produced output yet" being an inference, not an observation.
  2. **Non-directory accepted silently.** `touch data && leadminer doctor` prints
     `OK   data exists` and lists nothing: `Path.glob` returns an empty iterator when the
     parent is not a directory (verified on the local interpreter, Python 3.14.8; the
     `if not is_dir(parent_path)` guard is in `pathlib._Selector.select_from` for all
     supported versions). `exists()` is not `is_dir()`.
  3. **Never inspects content.** cli.py:219-220 only lists `f.name` and
     `f.stat().st_size`. A **0-byte `all_businesses.csv` prints as `OK`** with
     `0 bytes`. That is exactly the state `scrape.yml:74` (`if [ ! -s data/all_businesses.csv ]`)
     exists to prevent, and doctor cannot see it. The real checks already exist 80 lines
     above in `cmd_validate` (cli.py:135-201: blank names, BOM, coordinates outside both
     markets, rating out of 0-5, duplicate rate) — doctor just doesn't call them.
- **Trigger:**
  ```
  $ cd /tmp && leadminer doctor | sed -n '/data directory/,+1p'
  data directory:
    MISSING  data (no run has produced output yet)
  # ...while /Users/mhomsi/dev/dummy/leadminer/data/ holds 5 CSVs.
  ```
  ```
  $ cd /Users/mhomsi/dev/dummy/leadminer && mkdir -p data && : > data/all_businesses.csv
  $ leadminer doctor | sed -n '/data directory/,+2p'
  data directory:
    OK   data exists
         all_businesses.csv               0 bytes
  ```
  The next `leadminer run` loads that master, writes five 0-or-1-row CSVs, and CI's
  `ROWS -lt 100` guard fires *after* the pipeline has already burned an hour of API spend.
- **Fix:** anchor `DATA_DIR` to the package (`pathlib.Path(__file__).parent / "data"`, or
  a `--data-dir` flag), use `is_dir()`, and for `all_businesses.csv` delegate to
  `cmd_validate` and print its `problems` list.

### S2-2 — `doctor` is not wired into the one automated path that would use it

- **Where:** `.github/workflows/scrape.yml` (98 lines, no `doctor` step);
  `README.md:95`; `docs/audits/037-cli-design.md:653` ("Update `scrape.yml` to run
  `doctor`, `run`, `validate`, and `stats`").
- **Breaks:** the pre-flight exists only as a human habit documented in the README. The
  scheduled job (scrape.yml:9, weekly cron) goes straight from installing deps to
  `python main.py`, discovers a bad key or a blocked egress only after ~68 Places queries
  and three Overpass retries have burned time against a 300-minute budget
  (scrape.yml:25). `cmd_scrape` (cli.py:40-76) — the cheap single-source probe that would
  cost one query — is also never invoked in CI.
- **Trigger:** rotate `secrets.GOOGLE_PLACES_API_KEY` to a key without Places API (New)
  enabled. Monday 03:00 UTC the run starts, Google returns 403 on all 68 queries,
  `main.py:167-168` prints 68 stderr lines, and the job only fails ~an hour later at
  scrape.yml:80 if OSM+Wikidata fall under 100 rows.
- **Fix:** add `python -m cli doctor` (or `leadminer doctor`) as a step immediately before
  "Run scrapers", after S1-1/S1-2 make a non-zero exit meaningful.

### S3-1 — The declared input type carries no information; `args` is dead

- **Where:** `cli.py:204`; the body, cli.py:204-244, contains no `args.` access.
- **Breaks:** nothing today. But it invites `def cmd_doctor(args: argparse.Namespace) -> int`
  being copied as the house style for handlers that *do* read `args`, where the same
  annotation silently permits an `AttributeError`. `cmd_stats:81`, `cmd_validate:138` and
  `cmd_score:254` read undeclared `args.file` / `args.out`.
- **Fix:** either drop the parameter and register `cmd_doctor` via
  `functools.partial`-free lambda, or give the handlers a real protocol / a
  `Namespace` subclass per subcommand.

### S3-2 — `SCRAPER_EMAIL` asymmetry is undocumented and unexplained

- **Where:** `cli.py:210` (loop over both vars), `cli.py:213-214` (only the Google key
  clears `ok`).
- **Breaks:** the loop prints `MISSING  SCRAPER_EMAIL` and then exits 0, with nothing
  saying whether that is intended. It probably *is* intended (README.md:88 marks it
  "Recommended"), but the reader cannot tell a deliberate soft check from an oversight.
  Worth noting the cost is real but deferred: `httpclient.py:84-85` silently drops the
  email from the User-Agent, and the Overpass wiki asks apps to "add User-Agent or Referer
  headers to requests that uniquely identify your app" — so `doctor` reports green on a
  request that is being made *less* identifiable than the real one.
- **Fix:** print the required/recommended classification inline
  (`MISSING  SCRAPER_EMAIL  (recommended; Overpass asks for a contact)`), or add the
  `--strict` flag 037 proposed.

### S3-3 — "OK" means two different things in one output, with no legend and no summary

- **Where:** `cli.py:212` (`OK` = "env var is non-empty"), `cli.py:241` (`OK` = "HTTP
  status < 500"), `cli.py:243` (`FAIL`).
- **Breaks:** `OK` in the credentials block is a *presence* check; `OK` in the connectivity
  block is a *reachability* check. Three visual states (`OK`/`WARN`/`FAIL`) with three
  different severities, no legend, and no aggregate line — a script has to parse prose.
  Contrast the machine-readable discipline 040 proposed.
- **Fix:** prefix each line with a fixed-width code and add a trailing
  `result: N ok, N warn, N fail`.

### S3-4 — Doctor bypasses the project's own HTTP client, sending an anonymous User-Agent

- **Where:** `cli.py:226` (`import requests`) and `cli.py:239` (`requests.get`), versus
  `httpclient.get_session()` (httpclient.py:61-71) used by all three scrapers.
- **Breaks:** the probe sends `python-requests/2.32.3` instead of
  `leadminer/0.2 (+https://github.com/voxire/leadminer) (email)` (httpclient.py:85).
  Wikidata's WDQS has a descriptive-User-Agent policy and answers non-compliant clients
  with 403 — which, per S1-2, prints `OK`. So the probe can fail a request the real scraper
  would have made successfully, or succeed in a way that tells you nothing about the
  compliant request.
- **Fix:** `from httpclient import get_session` and reuse it, so doctor and production
  share one transport, one retry policy, and one identity.

### S3-5 — No test covers `cmd_doctor`; the type contract is unenforced

- **Where:** `tests/test_lead_signal.py` covers `cmd_stats` (`:211`) and `cmd_validate`
  (`:228`, `:242`, `:255`) but never `cmd_doctor`. `pyproject.toml:64-68` configures
  `mypy strict`, and mypy would flag `cli.py:37` (`Returning Any`/`got None, expected
  int`), but `.github/workflows/scrape.yml` has no lint or typecheck step. `ruff check
  cli.py` (ruff 0.16.10, local) reports 8 findings — `RUF010` ×6, `PTH123` ×2, `W292` —
  **none of them in cli.py:204-244**.
- **Breaks:** S1-3's return-type violation is detectable today by tooling that nobody
  runs. Doctor's exit-code logic is exactly the kind of thing two assertions pin down
  (`env` cleared → 3; `requests.get` raising → 4; both fine → 0).
- **Fix:** three `unittest.mock.patch` tests over `os.environ` and `requests.get`, plus a
  `ruff check` + `mypy` step in CI.

## Fields read or written that are not in `BusinessRecord`

Exhaustive, as asked. `BusinessRecord` is defined at `scrapers/base.py:5-28` with 22
required keys.

**Fields read: none. Fields written: none.** Lines cli.py:204-244 contain no subscript, no
`.get`, no record access of any kind. `cmd_doctor` does not import `csv` (cli.py:22
imports it at module level; `cmd_doctor` never uses it), never imports
`scrapers.base`, and never touches `main`.

What it *does* read, none of which is a record field:

| Read | Where | Type in practice |
|---|---|---|
| `os.environ["GOOGLE_PLACES_API_KEY"]` | cli.py:211 | presence only, via `bool()` — value never inspected |
| `os.environ["SCRAPER_EMAIL"]` | cli.py:211 | presence only |
| module global `DATA_DIR` | cli.py:26, 217 | `pathlib.Path` — **cwd-relative** |
| `data/*.csv` filenames | cli.py:219 | `str` |
| `f.stat().st_size` | cli.py:220 | `int` bytes |
| HTTP status codes | cli.py:240 | `int` from `requests.Response` |

Two notable *non*-reads, i.e. fields of `BusinessRecord` that would have made this
diagnostic worth its name and are simply not consulted:

- `source` (base.py:26) — would allow "last run collected N records from google_places /
  osm / wikidata", i.e. per-source freshness, which is the actual question an operator
  has when a run looks wrong.
- `scraped_at` (base.py:27) — would allow "master is 63 days stale". Currently
  impossible to answer from `leadminer doctor`.

**The declared/actual mismatch that *is* real in this file** is at the CSV boundary, not
here: `cmd_stats` (cli.py:86-87) and `cmd_validate` (cli.py:142-143) treat
`csv.DictReader` rows as if they were `BusinessRecord`, but a DictReader row is
`dict[str, str | list[str] | None]` — every cell is a **string**, whereas `base.py:11-12`
declares `lat: float | None`. cli.py:167 has to write

```python
lat, lon = float(r["lat"]), float(r["lon"])  # type: ignore[arg-type]
```

That `type: ignore` is the exact line where the two type systems are known to disagree,
and it is silenced rather than reconciled. Also note `base.py:5` is a `total=True`
TypedDict, so all 22 keys are statically required — but `main.load_master`
(main.py:86-104) returns `list[dict]` built from `DictReader`, which produces rows with
*missing* columns if the input CSV is short a column and an extra `None`-keyed list if it
has one. So records at runtime are not `BusinessRecord` in either direction, and
`cmd_score:266-272` then writes `country` / `industry_priority` / `recommended_service` /
`lead_score` onto those untyped dicts.

## Not a bug, but worth knowing

- **The ImportError guard is genuinely good.** cli.py:225-231 catches the one failure mode
  that matters for a diagnostic tool, and the comment at cli.py:228-229 states the
  intent. Keep it when you refactor.
- **`except Exception as e` around the probe is correct.** `requests` raises a wide tree
  (`ConnectionError`, `Timeout`, `SSLError`, `TooManyRedirects`, …) and
  `BaseException` is correctly not caught, so `Ctrl-C` still reaches cli.py:316.
- **`cli.py:206` `import os` is function-local** while `DATA_DIR` is module-global
  (cli.py:26). Harmless; slightly inconsistent.
- **Three sequential 5s probes = up to 15s.** Acceptable for a command you run by hand,
  but it is why doctor should not be a per-source parallel fan-out without thought.
- **`sorted(DATA_DIR.glob("*.csv"))` is top-level only**, which matches the CI layout
  (`scrape.yml:56`, `rclone copy ... --max-depth 1 --include "*.csv"`). Correct as is.
- **`leadminer doctor` costs nothing today** because the Google probe is a GET (S1-2).
  Fixing S1-2 makes doctor cost one billable Places request per invocation. Budget for
  that before wiring it into a weekly cron (S2-2), or use a non-billable key check.

## Recommended order of work

1. **S1-1** — thread connectivity results into the exit code; adopt 037's `3` (config) /
   `4` (connectivity) split. Smallest diff, largest effect: it makes every later fix
   observable. ~6 lines at cli.py:208-244.
2. **S1-2** — fix the threshold to `200 <= status < 300` first (one line, immediately
   turns today's false `OK`s into `FAIL`s), then replace the Places GET with a real
   authenticated POST and Overpass's `/api/status` with a cheap interpreter probe. Note the
   billing cost.
3. **S1-3** — drop the `or 0` at cli.py:315 and make `main.main()` return `int`. This is
   the one that publishes bad data rather than bad diagnostics, and it lives in
   `main.py`, which the brief marks read-only to auditors — flag it for an implementation
   agent.
4. **S2-2** — add the doctor step to `scrape.yml` (only worth doing after 1 and 2).
5. **S2-1** — anchor `DATA_DIR` to the package, `is_dir()` instead of `exists()`, and
   delegate master inspection to `cmd_validate`.
6. **S3-5, S3-1..4** — hygiene: tests for the exit-code matrix, `httpclient.get_session()`
   in doctor, one meaning per status word, and either document or delete the unused `args`.
