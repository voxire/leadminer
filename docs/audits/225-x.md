# 225 — `cmd_stats` hostile-input boundary review

**Target:** `cmd_stats` at `cli.py:79`. Python 3.14.8 (project targets 3.12; behaviour
verified identical on both — nothing below depends on version).

## Contract, as actually implemented

| Aspect | Reality | Anchors |
|---|---|---|
| Signature | `cmd_stats(args: argparse.Namespace) -> int` | `cli.py:79` |
| Sole input | `args.file`, a path string; argparse default `data/all_businesses.csv` | `cli.py:81`, `cli.py:294` |
| Returns | `0` success, `1` empty file, `2` missing file; **any** uncaught exception propagates | `cli.py:84`, `cli.py:90`, `cli.py:132` |
| Network | none, correct — no `requests` import in the call path | `cli.py:14-15` |
| Top-level guard | `main()` catches **only** `KeyboardInterrupt` | `cli.py:314-318` |
| Cell model | every value is a `str` (or `None`); **no numeric parsing at all** | `cli.py:87`, `cli.py:96` |
| Tri-state contract | `website_live` ∈ {`"True"`, `"False"`, `""`} | `cli.py:105-106`, `main.py:103` |

The last row is the load-bearing one: the function declares itself a **presence
counter** over raw CSV text, and never casts. That makes most hostile inputs
harmless and concentrates all the damage in four places: the header, the
decoder, the field-size limit, and the exact string comparisons on
`website_live`.

## Verdict

`cmd_stats` has **no input validation at all**. Every guard it does have is
incidental — `exists()` instead of `is_file()`, `utf-8-sig` instead of an
encoding sniff — and four distinct inputs escape them: a **leading blank line**
makes the command print an all-zero report and **exit 0**; a non-UTF-8 or
UTF-16 file, a field ≥ 128 KiB, and a directory path each raise an uncaught
traceback out of `main()`. The all-zero case is the dangerous one, because
`cli.py:80` advertises this command as *"the first thing to check"* — the tool
whose entire job is to be trustworthy when data looks wrong is the one thing
that lies.

## Findings

### S1 — A single leading blank line produces an all-zero report and exit code 0

- **Where:** `cli.py:87` (`rows = list(csv.DictReader(f))`), consumed at
  `cli.py:96`, `cli.py:107-110`, `cli.py:116`, `cli.py:120`, `cli.py:124`, `cli.py:129`.
- **Mechanism:** `csv.DictReader` skips empty physical rows when hunting for the
  header, and on a leading `\n` it settles on `fieldnames == []`. With empty
  fieldnames every row is packed into the **restkey** bucket, so each row becomes
  the dict `{None: [col0, col1, ...]}`. Every `r.get('phone')`, `r.get('email')`,
  `r.get('website')`, `r.get('website_live')` then returns `None`, and the
  `(None or "").strip()` guards at `cli.py:96`/`cli.py:107` swallow it into a
  falsy `""`. The row count is inflated too — the header line itself is counted
  as data, so `total` (`cli.py:92`) is **off by one**.
- **Breaks:** every one of the nine summary numbers reads `0`, every Counter
  section reads `None N`, and `cmd_stats` returns `0` from `cli.py:132`. Nothing
  in the output is distinguishable from "the pipeline collected nothing but
  shells".
- **Trigger:**
  ```
  printf '\nname,phone,email,website,website_live,region,industry_priority,recommended_service,source\nA,+96170000001,e@x.com,https://a.example,True,Beirut,high,Web Design,osm\n' > lead.csv
  leadminer stats lead.csv
  ```
  Observed output, exit `0`:
  ```
  lead.csv  (2 rows)          <-- file contains ONE record

    with phone      : 0
    with email      : 0
    with website    : 0
    with instagram  : 0
    with whatsapp   : 0
    with region     : 0

    website live    : 0
    website dead    : 0
    unreachable     : 0  (not the same as dead)

    by priority:
      None       2
  ```
  Verified intermediate state: `DictReader.fieldnames == []` and
  `list(reader) == [{None: ['name','phone',...]}, {None: ['A','+9617...',...]}]`.
- **Reachability:** `write_csv` (`main.py:124-129`) always emits `writeheader()`
  first and writes atomically via `.tmp` + `os.replace`, so leadminer's *own*
  master is immune. It is a human in the loop that breaks it — and the humans in
  this loop are exactly the ones the brief points at (`BRIEF.md:47-55`, "the
  product"), who open the CSV in Excel/Sheets to actually sell the leads, and
  who concatenate files with `cat`. Both leave a leading or trailing blank line.
- **Fix:** after building the reader, refuse to report on a header you do not
  recognise:
  ```python
  reader = csv.DictReader(f)
  missing = REQUIRED_STATS_COLUMNS - set(reader.fieldnames or ())
  if missing:
      print(f"{path}: not a leadminer CSV (missing {sorted(missing)[:5]}; "
            f"first line was {reader.firstlineno and open(path).readline()!r})",
            file=sys.stderr)
      return 2
  ```

### S1 — Any non-UTF-8 file kills the command with an uncaught `UnicodeDecodeError`

- **Where:** `cli.py:86`. The `open()` is not wrapped, and `main()` at
  `cli.py:314-318` catches only `KeyboardInterrupt`.
- **Breaks:** `leadminer stats` — the documented safe, no-network diagnostic —
  dies with a Python traceback instead of a message.
- **Triggers, all verified:**
  | Input | Exception |
  |---|---|
  | Arabic text in **cp1256** (default for Arabic-locale Windows/Excel) | `'utf-8' codec can't decode byte 0xe3 in position 11: invalid continuation byte` |
  | **UTF-16 with BOM** (Excel "CSV Unicode") | `'utf-8' codec can't decode byte 0xff in position 0: invalid start byte` |
  | a single stray non-UTF-8 byte (e.g. `0xe9` for `é` written as latin-1) | `'utf-8' codec can't decode byte 0xe9 in position 14: invalid continuation byte` |
  | `leadminer stats data/all_businesses.csv.gz` — gzip magic `1f 8b` | `'utf-8' codec can't decode byte 0x8b in position 1: invalid start byte` |
- **Why this is likely and not exotic:** the project exists to harvest Arabic
  business names (`BRIEF.md:7-9`) and deliberately writes `utf-8-sig` *"so Excel
  and Google Sheets detect UTF-8 and render Arabic business names correctly
  instead of mojibake"* (`main.py:118-119`). That same pipeline hands the file to
  Arabic-locale Excel, which round-trips it as cp1256. One human save breaks
  every offline command in the tool.
- **Fix:** sniff before decoding and degrade rather than die —
  `raw = path.read_bytes()`; if it starts with `1f 8b` say so and return 2; try
  `utf-8-sig`, then `cp1256` with `errors="replace"` plus a loud warning naming
  the substituted characters. `cmd_validate` (`cli.py:143`) has the identical
  defect and needs the same helper — factor it into one `_read_csv(path)`.

### S1 — A single field ≥ 128 KiB raises `csv.Error`, which `main()` does not catch

- **Where:** `cli.py:87`. `csv.field_size_limit()` is `131072` by default.
- **Breaks:** the whole file fails to parse, not just the one row. Uncaught.
- **Trigger:** one `website` or `address` value of 131,082 characters. The
  enricher harvests URLs and contact strings out of arbitrary scraped HTML, so a
  single `data:` URI, a minified inlined asset reference, or a base64 blob
  captured as a contact field is enough. Verified:
  ```
  csv.Error: field larger than field limit (131072)
    File ".../cli.py", line 87, in cmd_stats
      rows = list(csv.DictReader(f))
  ```
- **Note the asymmetry:** 100,000 characters passes fine. There is no
  application-level length cap, so behaviour flips from "works" to "process dies"
  on an invisible threshold nobody chose.
- **Fix:** `csv.field_size_limit(sys.maxsize)` once at import, plus
  `except csv.Error as e: print(...); return 2` around the read.

### S1 — `exists()` is not `is_file()`: directories and unreadable files traceback

- **Where:** `cli.py:82-86`.
- **Breaks:** `path.exists()` is `True` for directories, then `open()` raises.
  `IsADirectoryError` / `PermissionError` propagate through `main()`.
- **Triggers, all verified:**
  | Command | Result |
  |---|---|
  | `leadminer stats data` | `IsADirectoryError: [Errno 21] Is a directory: 'data'` — and `data/` is this repo's own default output directory (`cli.py:26`, `cli.py:294`) |
  | `leadminer stats ""` | `pathlib.Path("")` is `PosixPath('.')`, whose `exists()` is `True` → `IsADirectoryError: ... 'data'`/`'.'`. Reachable because the positional is `nargs="?"` (`cli.py:294`) so an empty argv element is accepted |
  | `chmod 000 f.csv; leadminer stats f.csv` | `PermissionError: [Errno 13] Permission denied` |
- **Fix:** `if not path.is_file(): print(f"not a readable file: {path}", file=sys.stderr); return 2`

### S2 — `website_live` values that violate the documented tri-state vanish from all three buckets

- **Where:** `cli.py:107-110`. The comment at `cli.py:105-106` *documents* the
  tri-state; the code implements it as exact, case-sensitive string equality.
- **Breaks:** `cli.py:109-110` defines "unreachable" as *has a website AND
  `website_live` is blank*, so a non-blank unrecognised value has nowhere to land.
  The three numbers silently under-count and, worse, are mutually inconsistent
  with `with website` printed 13 lines above — with no mechanism for the reader
  to notice.
- **Trigger:** `website_live` ∈ {`true`, `TRUE`, `1`, `yes`, `" True "`} with a
  non-empty `website`. Verified on a 9-row file:
  ```
    with website    : 7
    website live    : 1     <-- only the literal "True"
    website dead    : 1
    unreachable     : 3
  ```
  1 + 1 + 3 = 5, but 7 rows have a website. Two rows disappeared silently.
  Meanwhile `main.load_master` (`main.py:103`) coerces anything that is not
  exactly `"True"`/`"False"` to `None`, so the *pipeline* silently reclassifies
  `"true"` as unknown while `cmd_stats` silently reclassifies it as *nothing* —
  the two commands disagree about the same file.
- **Fix:** normalise and add a fourth bucket so the arithmetic closes:
  ```python
  wl = (r.get("website_live") or "").strip().lower()
  live = sum(1 for r in rows if wl in ("true", "1", "yes"))
  ...
  bad  = sum(1 for r in rows if r.get("website") and wl not in ("", "true", "false", "1", "0", "no"))
  print(f"  unrecognised   : {bad:,}   <-- not a website_live value; fix the producer")
  ```

### S2 — `list(csv.DictReader(f))` materialises the entire master in RAM

- **Where:** `cli.py:87`. `cmd_validate` repeats it at `cli.py:143`.
- **Breaks:** measured **667 bytes/row** for a 9-column file
  (`tracemalloc`, 100k rows: 6.8 MB on disk → 66.7 MB resident). The real schema
  is **22 columns** (`main.py:33-40`, `BRIEF.md:59-62`), so ~1.6 KB/row. The
  target file is `all_businesses.csv`, the *cumulative master, all time*
  (`BRIEF.md:51`), accumulating across runs. Extrapolated: **~0.8 GB at 500k
  rows**. There is no streaming, no size guard, no `--limit`.
- **Aggravating:** the docstring at `cli.py:80` markets this as *"the first thing
  to check"*, i.e. the command you reach for when a run looks wrong — on a
  laptop, at exactly the moment memory is least likely to be available. A swap
  storm here reads as "the tool is broken", not "the file is big".
- **Fix:** one streaming pass that accumulates `sum()` totals and four
  `collections.Counter`s, never building a list. The whole function needs no row
  retention and would get faster and O(1) in memory.

### S2 — `most_common(n)` truncates with no overflow marker, hiding categories

- **Where:** `cli.py:120` (`.most_common(8)`), `cli.py:125` (`.most_common(12)`),
  `cli.py:130` (`.most_common(8)`).
- **Breaks:** the reader has no way to tell a complete distribution from a
  truncated one. Verified on a file with **15 distinct `source` values**: eight
  printed, seven vanished, and no `... 7 more` line. An operator concludes the
  pipeline only ever talks to 8 sources.
- **Fix:** build the `Counter`, then print `min(n, ...)` entries followed by
  `f"    ... and {len(counter) - n} more"` when `len(counter) > n`. `source` and
  `region` are open-vocabulary (free text from OSM/Wikidata), so this will bite.

### S3 — Whitespace-only `region` yields invisible, duplicated buckets that contradict `with region`

- **Where:** `cli.py:124` — `r.get("region") or "Unknown"` applies **no
  `.strip()`**, while `count('region')` at `cli.py:103` **does** strip.
- **Breaks:** `"   "` is truthy, so it is not folded into `"Unknown"`, and it is
  then rendered through `f"{str(k):<20}"` as 3 spaces + 17 spaces of padding —
  a blank line. `"\t"` prints as a literal tab. Two different whitespace-only
  spellings become two separate buckets. Verified: a 3-row file reports
  `with region : 2` while the `by region` breakdown below it shows **three**
  buckets (`"   "`, `Beirut`, `"\t"`), none of which is `Unknown`.
- **Fix:** `(r.get("region") or "").strip() or "Unknown"`, and reuse one
  `_clean()` helper for `count()` and all four Counter sites so the two halves of
  the same report can never disagree again.

---

### S3 — `_fmt`'s `n/a` branch is dead code and its `float` arm is never exercised

- **Where:** `cli.py:29-30`, called only from `cli.py:98-103`.
- **Why it matters (barely):** the signature advertises `int | float | None`, but
  `count()` is `sum(1 for ...)` — always `int`, never `None`. The `None` path is
  unreachable and the `float` path is untested. Not a bug today; it is a trap for
  whoever adds `count('lead_score')` next, where `None` and `float` become real.
  Either narrow the annotation to `int` or actually use it.

## Not a bug, but worth knowing

- **Unicode is a non-issue here.** Nine unicode classes (Arabic, French,
  emoji, ZWJ, combining marks, ZWSP, RTL, BOM) all parse and print correctly.
  Every encoding failure in this function is a *byte-level* problem, never a
  *character-level* one. Don't spend hardening effort on normalisation.
- **`csv.Error` is the only exception type that can come from the parser**, and
  it is the only one nothing catches. `strict=False` also means the parser will
  never complain about malformed quoting — it will just under-count rows.
- **`cmd_validate` shares every structural defect of `cmd_stats`** (`cli.py:143`,
  `:154`, `:167`) and is the natural place to put the shared `_read_csv` /
  header-validation helper. Worth noting: on the leading-blank-line file,
  `validate` **does** fail correctly (exit 1, "every row has a blank name") while
  `stats` reports success. `stats` is the one that lies — which is backwards,
  since `validate` is the quality gate.
- **`_fmt` (`cli.py:29`) is not the risk it looks like.** `f"{n:,}"` accepts any
  `int`/`float` at any magnitude; there is no overflow. The dead `None` branch is
  the only issue.
- **No numeric column is read by `cmd_stats`.** That is why zero, negative, and
  float-shaped garbage are harmless *today*. The moment someone adds
  `count('lead_score')` or `count('review_count')`, the truthiness test at
  `cli.py:96` starts treating `"0"` as present. Add a numeric path deliberately
  or not at all.
- **Concurrency note, not my finding:** the repo root currently has three junk
  files named `" "`, `-`, and `0` (374 bytes each), evidently from another agent
  passing bare values to a `choices=`-constrained flag. I left them alone per
  the brief's rule 1.

## Recommended order of work

1. **Validate the header before reporting anything** (`cli.py:87`). One
   `REQUIRED_COLUMNS - set(reader.fieldnames)` check kills the entire silent-zero
   family — blank-line, UTF-16-LE, wrong-file — and converts the worst S1 into a
   loud `return 2`. Highest ratio of harm removed to lines changed.
2. **Stop `main()` from letting anything but `KeyboardInterrupt` escape**
   (`cli.py:314-318`), or wrap `cli.py:86-87` in
   `except (OSError, UnicodeDecodeError, csv.Error)`. Fixes the directory, the
   `""` argument, permissions, cp1256, UTF-16, gzip and the 128 KiB field all at
   once. Cheapest possible S1 fix in the file.
3. **`is_file()` instead of `exists()`** (`cli.py:82`) — one word, kills
   `leadminer stats data`.
4. **Add the `unrecognised` bucket and close the arithmetic** on
   `website_live` (`cli.py:107-113`), asserting
   `live + dead + unreachable + unrecognised == count('website')` so the report
   can never quietly contradict itself.
5. **Stream instead of `list()`-ing the master** (`cli.py:87`, and `cli.py:143`).
   Turns ~0.8 GB into a fixed handful of counters and makes `stats` viable on the
   cumulative master it is designed for.
6. **Honest truncation** at `cli.py:120`/`:125`/`:130`: print `... and N more`.
7. **One `_clean(value)` helper** for `cli.py:96` and the four Counter sites, so
   whitespace-only values can never again count in one section and vanish in
   another.

### Reproducing this report

Nothing here needs the network. Write the literal CSV bodies quoted above into a
temp file and run `python3 cli.py stats <file>`, watching the exit code — the
crash cases traceback out of `cli.py:322`, and the silent-wrong cases return `0`.
The header pathology is one line: `csv.DictReader.fieldnames` is `[]` whenever
the first non-empty physical line is blank.
