# 226-x — `cmd_stats` (cli.py:79): the tests it still needs

## Verdict

provably vacuous: I deleted the entire tri-state computation (`cli.py:107-110`)

## Findings

### S1 — Any boolean not spelled `True`/`False` vanishes from the report entirely

- **Where:** `cli.py:107-110`; the identical parser lives at `main.py:102-103`;
  `README.md:63` documents the field as `true` / `false`, never mentioning the
  third state.
- **Breaks:** a row whose `website_live` cell is `TRUE`, `false`, `1`, `0`,
  `yes`, or ` True`-with-a-trailing-space is counted in **none** of the three
  buckets. It is not "unknown" — it is *invisible*. The report prints
  `website live : 0 / website dead : 0 / unreachable : 0` next to
  `with website : 4`. An operator triaging a run concludes "we have four
  websites and none of them are broken", which is the opposite of the truth, and
  `unreachable : 0` in particular reads as *good news* — it is the number that
  says "our crawler is working".
- **Trigger (literal input, `website_live` cell varied, one row each):**

  ```
  name,website,website_live
  A,https://x.com,True
  B,https://x.com,False
  C,https://x.com,          <- blank
  D,https://x.com,TRUE
  E,https://x.com,true
  F,https://x.com,1
  ```

  Observed on the current code:

  ```
    with website    : 6

    website live    : 1
    website dead    : 1
    unreachable     : 1  (not the same as dead)
  ```

  Three of six rows are unaccounted for. The `TRUE` cell is the realistic
  trigger: `main.py:118-119` writes these CSVs **with a BOM specifically so
  Excel and Google Sheets open them correctly**, so the intended workflow is for
  a human to open `data/all_businesses.csv` in a spreadsheet, look at it, and
  save it. Both Excel and Google Sheets coerce the text `True` to a boolean and
  write `TRUE` back out.
- **Fix (one line):** stop re-implementing the parse. Have `cmd_stats` read
  through `main.load_master`, which already coerces the tri-state at
  `main.py:102-103`; or extract that coercion into one `tri_state(cell)` helper
  imported by both. Accept case-insensitively and `1`/`0`/`yes`/`no`, and
  **reject** anything unrecognised loudly rather than folding it into "unknown".
- **The test that catches it** — this is a genuine property, so state it as one:

  ```python
  def test_liveness_buckets_sum_to_with_website(self):
      """live + dead + unreachable == with website, for every spelling.

      Property, not an example: the three buckets must partition the rows that
      have a website. Any cell that is neither blank nor a recognised boolean
      today falls through all three predicates at cli.py:107-110.
      """
      for cell in ("True", "False", "", "TRUE", "FALSE", "true", "false",
                   "1", "0", "TRUE ", " True", "yes", "Yes"):
          with self.subTest(cell=cell), tempfile.TemporaryDirectory() as d:
              p = self.raw(d, [row(name="A", website_live=cell)])
              rc, out = self.stats(p)
              got = (self.numbers(out, "website live")
                     + self.numbers(out, "website dead")
                     + self.numbers(out, "unreachable"))
              self.assertEqual(got, self.numbers(out, "with website"),
                               f"cell {cell!r} fell out of the partition")
  ```

  **Verified result today:** 4 of 13 subtests pass (`"True"`, `"False"`, `""`,
  `" True"` — the last because `cli.py:107` strips), **9 fail**. This one test
  pins the original tri-state collapse (`cli.py:105-106`, `enricher.py:228-229`,
  `main.py:103`) *and* the new hole the fix opened.

### S2 — `exists()` is not `can be read`: three inputs produce a raw traceback

- **Where:** `cli.py:82-87`. `path.exists()` passes, then `open()` raises, and
  `main()` only catches `KeyboardInterrupt` (`cli.py:314-318`), so the
  traceback reaches the user and the process exits 1.
- **Breaks:** verified three ways, each with the exact exception:

  | Input | Result |
  |---|---|
  | `leadminer stats data` (a directory) | `IsADirectoryError: [Errno 21] Is a directory: '…/tmp22l29_b1'` |
  | a CSV containing `b"Caf\xe9"` | `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9 in position 15` |
  | `chmod 000` on a valid CSV | `PermissionError: [Errno 13] Permission denied` |

  This directly violates the exit-code contract this project wrote for itself —
  `docs/audits/037-cli-design.md:407-409` specifies `2` for *"File not found **or
  unreadable**"* — and it violates a principle already stated in the same file at
  `cli.py:228-229`: *"doctor exists to diagnose a broken environment, so it must
  never be the thing that tracebacks."* The same principle plainly applies to a
  command whose docstring at `cli.py:80` says "This is the first thing to check."
  A traceback is also the worst possible first impression for the operator who
  opened a terminal because the data looks wrong.
- **Trigger:** `cmd_stats(argparse.Namespace(file=<any unreadable path>))`.
- **Fix (two lines):** `if not path.is_file(): … return 2` for the directory
  case, and wrap the `open()` in `except (OSError, UnicodeDecodeError)` → print
  one line to stderr, `return 2`.
- **The tests that catch it** — one method per failure mode, because the fix for
  one will not fix the others:

  ```python
  def test_directory_argument_is_exit_2(self):
      with tempfile.TemporaryDirectory() as d:
          rc, out = self.stats(d)
      self.assertEqual(rc, 2)
      self.assertNotIn("Traceback", out)

  def test_latin1_bytes_are_exit_2(self):
      with tempfile.TemporaryDirectory() as d:
          p = Path(d) / "f.csv"
          p.write_bytes(b"name,region\nCaf\xe9,Beirut\n")
          rc, out = self.stats(p)
      self.assertEqual(rc, 2)
      self.assertNotIn("Traceback", out)

  def test_unreadable_permissions_are_exit_2(self):
      if os.geteuid() == 0:
          self.skipTest("root ignores mode bits")
      with tempfile.TemporaryDirectory() as d:
          p = self.raw(d, [row()])
          p.chmod(0o000)
          try:
              rc, out = self.stats(p)
          finally:
              p.chmod(0o600)
      self.assertEqual(rc, 2)
      self.assertNotIn("Traceback", out)
  ```

  **Verified result today: all three ERROR** (the exception propagates out of
  `cmd_stats`, which is a stronger failure signal than a failed assertion).
  `test_zero_byte_and_header_only_are_exit_1` passes today — 0-byte and
  header-only files both take the `cli.py:88-90` path and return 1. Keep it.

### S2 — The report contradicts itself: two different definitions of "has a website"

- **Where:** `cli.py:96` counts `website` with `.strip()`; `cli.py:110` counts it
  with bare truthiness. Same file, same report, two answers.
- **Breaks:** two ways, both observed:

  | Literal row | Observed output | Problem |
  |---|---|---|
  | `website="   "` (3 spaces), `website_live=""` | `with website : 1`, `unreachable : 1` | a row with no website is reported as an unreachable website |
  | `website=""`, `website_live="True"` | `with website : 1`, `website live : 2` | **more live sites than websites** |

  The second is not hypothetical: `docs/audits/048-data-quality-validation.md:45`
  and `:311` both classify exactly this as `ERR_REF_ORPHAN_LIVENESS`, FATAL,
  because `main.load_master` parses `website_live` independently of `website`
  (`main.py:102-103`). So the project already knows this state exists. When it
  does, `cmd_stats` prints a live-site count that exceeds its own website count,
  and no arithmetic on the report can be trusted.
- **Fix:** one `has_website = bool((r.get("website") or "").strip())` predicate,
  used by `count("website")`, by the `unknown` comprehension, and by the
  `live`/`dead` comprehensions — so the three buckets are computed over exactly
  the population `with website` reports.
- **The tests that catch it:**

  ```python
  def test_orphan_liveness_is_not_reported_as_live(self):
      """website_live is only meaningful for a row that has a website."""
      with tempfile.TemporaryDirectory() as d:
          p = self.raw(d, [row(name="A", website="", website_live="True")])
          rc, out = self.stats(p)
      self.assertEqual(rc, 0)
      self.assertEqual(self.numbers(out, "with website"), 0)
      self.assertEqual(self.numbers(out, "website live"), 0)

  def test_whitespace_website_is_not_an_unreachable_site(self):
      with tempfile.TemporaryDirectory() as d:
          p = self.raw(d, [row(name="A", website="   ", website_live="")])
          rc, out = self.stats(p)
      self.assertEqual(self.numbers(out, "with website"), 0)
      self.assertEqual(self.numbers(out, "unreachable"), 0)
  ```

  **Verified result today: both fail** (`1 != 0` on `website live` and on
  `unreachable` respectively). The first should arguably be a *warning* rather
  than a silent reclassification — `cmd_validate` is the right place to fail on
  it, and `048:311` already defines the rule code.

### S2 — Three capped histograms silently drop rows, with no marker

- **Where:** `cli.py:120` (`most_common(8)`), `cli.py:125` (`most_common(12)`),
  `cli.py:129` (`most_common(8)`). `by priority` at `cli.py:116` is uncapped.
- **Breaks:** the printed buckets do not sum to the row count and nothing says so.
  Observed with ten rows carrying ten distinct `source` values:

  ```
    by source:
      (blank)                      1     <- dropped? no: this one printed
      osm                          1
      wikidata                     1
      google_places                1
      osm|wikidata                 1
      osm|google_places            1
      wikidata|google_places       1
      osm|wikidata|google_places   1
  ```

  Eight buckets, nine rows counted, two values (the blank and `"ZZZ"`) simply
  gone, and the literal string `more` appears nowhere in the output. A reader
  checking coverage sees a plausible-looking top-8 and concludes "we have 9
  sources' worth of coverage" when 2 of 10 rows are unaccounted for. Same shape
  for `by region` (12 of 13 verified) and `top pitches`.
  `by source` is the worst of the three: `dedup.py:173-174` unions multi-source
  provenance into `a|b` strings (`README.md:69` documents
  `osm|google_places`), so the histogram mixes atomic sources with composites in
  one bar list and the operator cannot tell which scraper earns its API cost.
- **Fix:** when `len(counter) > cap`, print a trailing line —
  `    … 3 more values, 3 rows (N distinct total)`. Make the cap a `--top`
  argument, as `docs/audits/037-cli-design.md:397` already specifies.
- **The test that catches it** — one property, parameterised over the three
  sections and their three different caps:

  ```python
  CAPPED = (("by source:", "by region:", 8),
            ("by region:", "top pitches:", 12),
            ("top pitches:", "ZZZEND", 8))

  def test_capped_histogram_declares_its_overflow(self):
      for section, nxt, cap in self.CAPPED:
          with self.subTest(section=section), tempfile.TemporaryDirectory() as d:
              rows = []
              for i in range(cap + 3):
                  kw = {"name": f"N{i}"}
                  if section == "by source:":
                      kw["source"] = f"s{i}"
                  elif section == "by region:":
                      kw["region"] = f"R{i}"
                  else:
                      kw["recommended_service"] = f"P{i}"
                  rows.append(row(**kw))
              rc, out = self.stats(self.raw(d, rows))
              buckets = self.buckets(out, section, nxt)
              self.assertEqual(len(buckets), cap)
              self.assertEqual(sum(n for _, n in buckets), cap,
                               "rows dropped with no marker")
              self.assertIn("more", out.lower())
  ```

  **Verified result today: all three subtests fail.** Note the assertion
  `sum == cap` is deliberate: it encodes "every printed bucket is honest and the
  report admits the rest are missing". Today the counts sum to `cap + 2` for
  sources because the tie-break order put the blank bucket first.

### S2 — Missing columns and blank cells print `None` or nothing at all as if they were data

- **Where:** `cli.py:116-117`, `cli.py:129-131`. Only region has a fallback
  (`cli.py:124`, `or "Unknown"`).
- **Breaks:** three different renderings of "no value", depending on which kind
  of absence it is:

  | Input | Rendered bucket |
  |---|---|
  | column absent from the header | `None       1` (`str(None)` at `cli.py:117`) |
  | column present, cell empty | `               10` — 15 spaces, no label |
  | `region` column present, cell empty | `Unknown              10` |

  The `None` case is the dangerous one: it is indistinguishable from a real
  priority value of `"None"`, and `cmd_stats` is routinely pointed at files that
  are not the master — `docs/audits/037-cli-design.md:487` shows
  `leadminer stats data/test_scored.csv`, and a pre-scoring CSV has no
  `industry_priority` column at all. Verified output on such a file:

  ```
    by priority:
      None       2
  ```

  An operator reads "None 2" as a priority bucket that needs investigating. It
  means the column does not exist.
- **Fix:** one `_label(v)` helper returning `"(blank)"` for `None`/`""`/whitespace
  and the literal column name for an absent key; use it at all four call sites.
- **The tests that catch it:**

  ```python
  def test_every_bucket_has_a_visible_label(self):

  def test_absent_column_is_labelled_not_none(self):

          p = self.raw(d, [{k: v for k, v in BASE.items() if k in hdr}], header=hdr)
  ```

  **Verified result today: both fail.** A stronger version of the second test

### S3 — Placeholder text is counted as a live contact channel

- **Where:** `cli.py:95-103`, `count()` accepts any non-blank cell.
- **Breaks:** every value in the project's own placeholder set
  (`docs/audits/048-data-quality-validation.md:419`:
  `{"unknown","n/a","none","null","-","--","restaurant","shop","store","test"}`)
  is counted as a filled channel. Verified: a single row with
  `phone="n/a", email="None", website="-", instagram="null", whatsapp="--"`
  reports `with phone : 1 / with email : 1 / with website : 1 /
  with instagram : 1 / with whatsapp : 1`. `docs/audits/048:117` already lists
  the same requirement for `name`.
- **Honest scoping:** the root cause is not in this function. `main.load_master`
  maps only `""` to `None` (`main.py:87-89`), so sentinels survive into the
  pipeline, where `enricher.lead_score` scores them by truthiness
  (`enricher.py:288-295`: `if record.get("email")` → +20,
  `if record.get("whatsapp")` → +15, `if record.get("instagram")` → +10). That
  is an **S1 in `enricher.py`, not here** — flagging it so it is not lost, but
  the fix belongs in one normalising pass in `load_master`. `cmd_stats` is
  simply where it becomes *visible*, which is why it is worth a test here: it is
  the canary for a bug that costs up to 45 points of `lead_score`.
- **The test that catches it** — a property over the canonical sentinel list:

  ```python

                                   instagram=s, whatsapp=s, region=s)])
              rc, out = self.stats(p)
              for field in ("with phone", "with email", "with website",
                            "with instagram", "with whatsapp", "with region"):
  ```

  **Verified result today: 12 of 14 subtests fail** (only `""` and `" "` are
  correctly excluded, by the `.strip()` at `cli.py:96`). Note that failing this

## The paste-ready module

Everything above, in one file. Helpers first — note the raw writer is
deliberate, see the note below it.

```python
import argparse, contextlib, csv, io, os, tempfile, unittest
from pathlib import Path

from cli import cmd_stats          # tests/test_lead_signal.py already puts the
                                   # repo root on sys.path at line 20

FIELDS = ["name", "category", "region", "country", "address", "lat", "lon",
          "phone", "email", "website", "website_live", "facebook", "instagram",
          "whatsapp", "linkedin", "rating", "review_count",
          "completeness_score", "lead_score", "industry_priority",
          "recommended_service", "source", "scraped_at"]

BASE = {f: "" for f in FIELDS}
BASE.update({"name": "Cafe", "category": "cafe", "region": "Beirut",
             "country": "LB", "address": "1 St, Beirut", "lat": "33.89",
             "lon": "35.50", "phone": "70123456", "website": "https://x.com",
             "website_live": "True", "rating": "4.2", "review_count": "12",
             "completeness_score": "2", "lead_score": "30",
             "industry_priority": "high", "recommended_service": "SEO audit",
             "source": "osm", "scraped_at": "2026-01-01T00:00:00Z"})


def row(**kw):
    r = dict(BASE)
    r.update(kw)
    return r


class StatsBase(unittest.TestCase):
    def raw(self, d, rows, header=FIELDS):
        """Write a CSV verbatim.

        Do NOT reuse main.write_csv here: it prints "  Written: …" to stdout
        (main.py:134), which lands inside any redirect_stdout block. The
        existing fixture at tests/test_lead_signal.py:208 gets away with it only
        because it runs outside the capture.
        """
        p = Path(d) / "f.csv"
        with open(p, "w", newline="", encoding="utf-8") as f:
            w = csv.DictWriter(f, fieldnames=header, extrasaction="ignore")
            w.writeheader()
            w.writerows(rows)
        return p

    def stats(self, path):
        buf = io.StringIO()
        with contextlib.redirect_stdout(buf), contextlib.redirect_stderr(buf):
            rc = cmd_stats(argparse.Namespace(file=str(path)))
        return rc, buf.getvalue()

    def numbers(self, out, label):
        for line in out.splitlines():
            if line.strip().startswith(label):
                return int(line.split(":", 1)[1].split()[0].replace(",", ""))
        return None

    def buckets(self, out, section, nxt):
        block = out.split(section)[1].split(nxt)[0]
        return [(ln.strip(), int(ln.split()[-1].replace(",", "")))
                for ln in block.splitlines() if ln.strip()]
```

## What genuinely cannot be tested here, and why

1. **Whether a `website_live` verdict is true.** `cmd_stats` reads a string out
   of a CSV (`cli.py:107`). The verdict is made over the network in
   `enricher._fetch_website` (`enricher.py:135-222`). No test of this function
   can prove a site is dead — only that the report transmits the CSV faithfully.
   Verifying the verdict needs recorded fixtures (`docs/audits/032-fixtures-offline-replay.md`)
   or cassette replay (`docs/audits/031-test-suite-design.md:17`), which is out
   of scope here and touches the network prohibition in `BRIEF.md:73-74`.
2. **Whether the report is *useful*.** "Is 12 the right top-N for regions" and
   "should `unknown` come first" are product decisions. They cannot be pinned
   until `--top` (`docs/audits/037-cli-design.md:397`) exists and someone picks
   the numbers. Pinning today's 8/12/8 as correct would enshrine a magic number.
3. **Peak memory on a real master.** `cli.py:87` does
   `rows = list(csv.DictReader(f))`, holding the entire file as dicts. You *can*
   assert a ceiling with `tracemalloc`, but the threshold is machine-dependent
   and the test becomes slow and flaky; that belongs in a benchmark, not the
   unit suite (`docs/audits/052-memory-streaming.md` owns the streaming redesign).
   What is cheap and I did run: 1,234 rows format correctly and fast.
4. **A torn read while a run rewrites the file.** Not deterministic to test, and
   not a real risk: `write_csv` writes to a temp file and `os.replace`s it
   (`main.py:124-130`), so a concurrent reader sees either the old file or the
   new one. The workflow's `concurrency` group (`scrape.yml:19-21`) prevents
   two runs racing anyway. No test needed.
5. **Python 3.12 vs the 3.14.8 I ran on.** `pyproject.toml:8` and
   `scrape.yml:34` pin 3.12; this sandbox only has 3.14.8. Everything above is
   stdlib `csv`/`argparse`/`os` behaviour that has not changed, but re-run the
   table in CI on 3.12 before trusting it. In particular I could **not**
   produce a `csv.Error` from an embedded NUL byte on 3.14 (`rc == 0`, the byte
   passes through). Older CPython raised `line contains NUL`; if 3.12 does, it
   belongs with the S2-1 unreadable-input family. I am not listing it as a
   finding because I could not reproduce it here.
6. **Whether `rc == 1` for a header-only file is the right answer.** A 0-byte
   file and a header-with-no-data-rows both print `is empty` and return 1
   (`cli.py:88-90`), but they are different situations and an operator debugging
   a truncated export needs to tell them apart. The current behaviour is
   testable (it is, and it passes); whether it is *correct* needs a contract
   decision first, so I have not proposed an assertion for it.
7. **Duplicate column names in the header.** Verified: `csv.DictReader` keeps the
   last value and `cmd_stats` does not crash. It belongs to `cmd_validate`
   (schema checking), not here.

## Not a bug, but worth knowing

- **Determinism is fine today.** `Counter.most_common` breaks ties by insertion
  order, which is a function of file order only — verified byte-identical across
  two runs of the same file. Worth *pinning* precisely so a future "sort by count
  desc" refactor cannot make the report churn between runs.
- **Stream discipline is already correct.** Diagnostics go to stderr
  (`cli.py:83`, `cli.py:89`), the report goes to stdout. That is the right split
  for `docs/audits/037-cli-design.md:591`'s `$GITHUB_STEP_SUMMARY` use, and it
  is the one thing the existing tests get right. Two cheap tests protect it.
- **Short rows and surplus cells do not crash.** A row with fewer fields than the
  header yields `None` values, absorbed by `(r.get(field) or "")` at `cli.py:96`;
  a row with more fields lands under the `None` restkey and is ignored. Verified
  on both. This is a real strength of the `or ""` idiom, repeated at every access
  site.
- **`cmd_stats` is not in CI.** `scrape.yml` runs `python main.py` plus inline
  shell checks (`scrape.yml:69-81`) and never invokes the CLI;
  `docs/audits/037-cli-design.md:653` says it should. Until that lands, every
  test in this file is the only guard there is — which is why the existing one
  being vacuous matters more than it looks.
- **`cmd_validate` has the same `exists()` hole** (`cli.py:137-142`) and the same
  missing-`is_file()` problem. Out of my scope; flagging it so it gets the same
  three tests rather than being rediscovered.
