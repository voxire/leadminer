# 246 — `cmd_doctor` dependency map: the health check wired to nothing that owns its facts

## Verdict

`cmd_doctor` (`cli.py:204-244`) has a **transitive dependency closure of exactly two
imports** — `os` (`cli.py:206`) and `requests` (`cli.py:226`) — plus one module
global, `DATA_DIR` (`cli.py:26`). That is the smallest closure of any command in
the file, and it should be the tell: it does **not** import `httpclient`
(whose comment at `httpclient.py:75-77` states that Overpass and Wikidata both
require an identifying User-Agent), it does not import `main` (which owns the
five output filenames it is supposed to verify), and it does not import
`google_places` (which owns the only credential it hard-fails on). Every fact
`doctor` asserts is coupled to its owner by a **duplicated string literal**, not an
import edge. The result is a function whose correctness depends on four
copies of four constants staying byte-identical forever, and for which the
obvious repair — route the probes through the shared HTTP layer — **closes a real
import cycle**, because `httpclient` already has `scrapers.osm`,
`scrapers.wikidata` and `scrapers.google_places` importing *it*.

> **Scope note.** `247-x.md` covers `cmd_doctor`'s *semantics* (exit codes,
> probe construction, signal quality) and `030-packaging-import-hygiene.md`
> covers the *repo-wide* src-layout break. Neither produces the transitive
> closure or identifies the cycle-closing edge. Findings 3, 4 and 6 below are
> new; findings 1, 2 and 5 corroborate `247` from the dependency direction and
> show that its recommended fixes are incomplete without a layering change first.

Two properties of this graph drive everything below:

1. **`httpclient` is the root sink.** Every network-touching module imports it;

### 1.3 `DATA_DIR` is two independent facts

```
cli.py:26    DATA_DIR = pathlib.Path("data")
main.py:41   DATA_DIR = pathlib.Path("data")
```

Two definitions, byte-identical, no shared source, no import between the modules
that define them. `cmd_doctor` reads `cli.py`'s copy; the pipeline writes
`main.py`'s copy (`main.py:208-213`). Nothing keeps them in agreement.

## Findings

### S1 — Routing doctor's probes through the shared HTTP layer closes an import cycle, so the layering defect is unfixable in place

- **Where:** `cli.py:239` (`requests.get`) against `scrapers/osm.py:4`,
  `scrapers/wikidata.py:4`, `scrapers/google_places.py:27`
  (`from httpclient import ...`), and `enricher.py:128`
  (`from httpclient import DEFAULT_MAX_BODY_BYTES, get_session`).
- **Breaks:** `247-x.md` recommends doctor perform the *pipeline's* requests
  rather than an unrelated probe. The pipeline's requests go through
  `httpclient.fetch_with_retry`. To do that, `cli` must know the endpoints, and
  the endpoints are owned by the scraper modules — which import `httpclient`.
  The moment `httpclient` gains an endpoint registry so that `cli` does not have
  to reach around it:
  ```
  httpclient  ──►  scrapers.osm            ──►  httpclient      # cycle
  httpclient  ──►  scrapers.wikidata       ──►  httpclient      # cycle
  httpclient  ──►  scrapers.google_places  ──►  enricher ──► httpclient   # 3-deep cycle
  ```
  The graph in §1.2 is acyclic *only* because `httpclient` is a leaf. The
  obvious fix for doctor's worst defect converts a functional defect into an
  `ImportError` at console-script startup.
- **Trigger:** add `ENDPOINTS = {...}` to `httpclient.py` and reference it from
  `cli.py:233`. `import cli` → `leadminer` console script (`pyproject.toml:33`)
  → `ImportError: cannot import name 'fetch_with_retry' from partially
  initialized module 'httpclient'`. Every command breaks, not just `doctor`.
- **Fix:** extract the *infrastructure* before the registry. Create
  `leadminer/endpoints.py` holding `OVERPASS_URL`, `SPARQL_ENDPOINT`,
  `PLACES_API_URL` and the credential-name constants, imported by `osm.py`,
  `wikidata.py`, `google_places.py`, `httpclient.py` **and** `cli.py`. Keep
  `httpclient` a leaf: no first-party imports, ever. Doctor then imports
  `endpoints` and `httpclient`, both of which sit below it.

### S2 — The credential doctor hard-fails on is owned by a module it cannot import; a rename silently disarms the check

- **Where:** `cli.py:210` and `cli.py:213-214`, versus
  `scrapers/google_places.py:157` and `httpclient.py:81`.
- **Breaks:** `ok` is set `False` only when the *string*
  `"GOOGLE_PLACES_API_KEY"` is absent from the environment. There is no import
  edge to the module that reads it, so nothing keeps the two in step. Rename the
  variable in `google_places.py:157` (a one-token change) and `doctor` starts
  reporting `MISSING GOOGLE_PLACES_API_KEY` forever while the pipeline is
  perfectly configured. The operator's only remedy — export the variable the tool
  asked for — is a no-op, and `google_places.py:169-171` will silently
  `return` with zero records, which `main.py` reports as a healthy run.
- **Trigger:** edit `scrapers/google_places.py:157` to
  `os.environ.get("PLACES_API_KEY")`. Run `leadminer doctor` with
  `PLACES_API_KEY` set and `GOOGLE_PLACES_API_KEY` unset. Output:
  `MISSING  GOOGLE_PLACES_API_KEY` and `return 1` — a false alarm against a
  correct configuration. Invert: leave `GOOGLE_PLACES_API_KEY` set to a stale
  value and `PLACES_API_KEY` unset; `doctor` prints `OK` and the pipeline
  produces no Saudi data at all.
- **Fix:** one module owns both names and both consumers import them. See the
  S1 fix — `endpoints.py` (or `config.py`) exports `GOOGLE_PLACES_API_KEY_ENV`
  and `SCRAPER_EMAIL_ENV`; `cli.py:210` and `google_places.py:157` and
  `httpclient.py:81` all read those constants.

### S2 — `cmd_doctor` is the only outbound call in the codebase that bypasses `httpclient`, so it is the only one that cannot reproduce the pipeline's network identity

- **Where:** `cli.py:239` — `grep -rn 'requests\.\(get\|post\|put\|head\)' --include='*.py' .`
  returns **exactly one hit**, this line.
- **Breaks:** every other outbound request in the repository acquires its
  Session from `httpclient.get_session()` (`httpclient.py:61-71`), which stamps
  `User-Agent: leadminer/0.2 (+https://github.com/voxire/leadminer)`
  (`httpclient.py:74-85`) and `Accept-Language`. `requests.get()` at
  `cli.py:239` builds a throwaway `requests.api` Session per call and sends
  `python-requests/2.32.3` instead. The codebase's own comments state this is
  required: `httpclient.py:75-77` — *"Overpass and Wikidata both ask for a
  contact address in the UA"* — and `README.md:88` — *"Contact address sent in
  the User-Agent, which Overpass and Wikidata both ask for."* So the two hosts
  whose UA policy is the entire stated reason `SCRAPER_EMAIL` exists are probed
  by the one call site that cannot send it. Doctor's verdict on those two rows
  is evidence about a request the pipeline never makes.
- **Trigger:** export `SCRAPER_EMAIL`, then run `leadminer doctor`. Both
  `requests.get` calls at `cli.py:239` go out with no contact address, while
  `osm.py:35` and `wikidata.py:74` in the same environment would go out with one.
  If the WDQS or Overpass edge declines the anonymous UA (403 / 429), `doctor`
  prints `FAIL` for a host the pipeline reaches fine — or, because
  `cli.py:240` only surfaces a status when it is `>= 500`, prints `OK` with no
  status at all.
- **Fix:** `from httpclient import get_session` and use
  `get_session().get(url, timeout=5)` (or `fetch_with_retry(..., retries=1)`).
  Once S1 is addressed this is a one-line change; before S1 it cannot be made at
  all.

### S2 — `f.stat()` is the one unguarded filesystem call in a function whose own comment promises it can never traceback

- **Where:** `cli.py:220`. Contrast the deliberate guard at `cli.py:225-231`,
  whose comment reads *"doctor exists to diagnose a broken environment, so it
  must never be the thing that tracebacks."*
- **Breaks:** the guard is applied to exactly one dependency (`requests`) and not
  to `pathlib`, whose `stat()` is reached on a path obtained from a separate
  `glob()` call. A dangling symlink is yielded by `Path.glob` (the pattern is
  non-recursive, so no `stat` gates the yield) and then `stat()` follows it and
  raises.
- **Trigger (reproduced, no network):**
  ```
  mkdir -p /tmp/probe/data && ln -s /nonexistent/target.csv /tmp/probe/data/all_businesses.csv
  cd /tmp/probe && python cli.py doctor
  ```
  Actual output:
  ```
  File "/…/cli.py", line 220, in cmd_doctor
      print(f"       {f.name:<32} {f.stat().st_size:,} bytes")
  FileNotFoundError: [Errno 2] No such file or directory: 'data/all_businesses.csv'
  ```
  Exit code 1 from the traceback, not from the health logic — indistinguishable
  from `cli.py:231`'s deliberate `return 1`.
- **Fix:** wrap `:217-222` in `try/except OSError` and report
  `UNREADABLE <name>` for that row, continuing with the rest.

### S2 — `doctor` reports on `data/` using a filename set it has no dependency on, so four missing exports are invisible

- **Where:** `cli.py:219` (`DATA_DIR.glob("*.csv")`) versus `main.py:209-213`,
  which writes exactly `all_businesses.csv`, `qualified_businesses.csv`,
  `with_websites.csv`, `without_websites.csv`, `sales_ready.csv`.
- **Breaks:** doctor imports `main` in three other commands (`cli.py:35`,
  `:249`) but not in `cmd_doctor`, so it has no notion of the expected set. It
  prints whatever bytes are on disk, in whatever order the filesystem yields,
  with no notion of missing or unexpected. `DATA_DIR.exists()` at `cli.py:217`
  is the strongest statement made about the data directory and it is satisfied
  by an empty directory.
- **Trigger (reproduced, `requests` stubbed):** `data/` containing only
  `all_businesses.csv` (7 bytes) and a stray `notes.csv` (3 bytes):
  ```
  data directory:
    OK   data exists
         all_businesses.csv               7 bytes
         notes.csv                        3 bytes
  ```
  Four of the five production exports are absent and `doctor` returns 0. A
  directory containing *only* `notes.csv` produces the same `OK`.
- **Fix:** `from .main import OUTPUT_FILES` (add that constant next to `FIELDS`
  at `main.py:33`) and diff the glob result against it.

### S3 — `DATA_DIR`'s duplication at `cli.py:26` / `main.py:41` is a cycle-avoidance hack the flat layout conceals

- **Where:** `cli.py:26`, `main.py:41`.
- **Breaks:** the obvious de-duplication is `from main import DATA_DIR` in
  `cli.py`. Today that is legal (`cli` → `main` is already an edge at
  `cli.py:35`). It stops being legal the moment `main` needs anything from
  `cli` — and it is about to: `main.py` has no config surface, no output-file
  registry, and no logging setup, all of which a real fix for S1/S2 wants to
  import from a shared place, while `cli` will want `main`'s `DATA_DIR` back.
  The duplication is not laziness; it is the flat layout's cycle budget spent in
  advance, and it will look like laziness to the next reader.
- **Fix:** resolve the path once, in the same `endpoints.py`/`config.py` module
  from S1, from an explicit `--data-dir` argument with a documented default.
  Neither `cli.py:26` nor `main.py:41` should own it.

### S3 — Imports that exist only for a side effect, or not at all

The lens asked specifically. In the closure of `cmd_doctor` and its immediate
neighbourhood:

- **`cli.py:46` — `from scrapers.base import BaseScraper  # noqa: F401  (import check)`.**
  `BaseScraper` is imported and never referenced. The dependency is *entirely*
  the `ImportError` side effect. This is the only deliberate
  side-effect-only import in the file and it is correctly marked with `# noqa`
  and an explanatory comment — worth keeping as the pattern, and worth noting
  that no tool in `pyproject.toml` verifies it still works (there is no import
  smoke test; `087-SYNTH-test-gap.md:19` confirms `cmd_doctor` is untested).
- **`enricher.py:2` — `import requests` is entirely dead.** `grep -n requests
  enricher.py` returns line 2 and line 125, and line 125 is inside a comment.
  `enricher` uses `httpclient.get_session()` (`enricher.py:128`) and never
  touches `requests` directly. This is the only first-party module-level
  third-party import in the tree that is unused.
- **`osm.py:1` / `wikidata.py:1` — `import logging`, and `log =
  logging.getLogger(__name__)` at `osm.py:7` / `wikidata.py:7`, are both dead.**
  `grep -rn 'log\.\(debug\|info\|warning\|error\|exception\)'` matches only
  `httpclient.py:178` and `:204`. The two scrapers that the Overpass and
  Wikidata probes are meant to watch build a logger and never emit through it.
- **`enricher.py:327-328` — `import urllib3` inside `enrich()`, used only for
  `urllib3.disable_warnings(...)`.** No name from it is used. It is also an
  **undeclared dependency**: `pyproject.toml:16-18` declares `requests` and
  nothing else, and `urllib3` is currently only present because `requests`
  depends on it. `doctor` verifies importability of `requests` (`cli.py:226`)
  and not of `urllib3`, so it certifies an environment it has not fully checked.

### S3 — Doctor and the module that owns the pipeline's failure taxonomy share no output channel

- **Where:** `cli.py` uses bare `print` throughout (`:212`, `:218`, `:220`,
  `:241`, `:243`). `httpclient.py:35` imports `logging`, `:45` creates a
  logger, and `:178` / `:204` emit `log.debug` for every transport error and
  every backoff decision. `grep -rn basicConfig --include='*.py' .` → **no
  matches**.
- **Breaks:** without `basicConfig`, `httpclient`'s two `log.debug` calls go to
  the `lastResort` handler at WARNING level and are discarded. Every retry,
  every `Retry-After` honoured, every jittered backoff in the pipeline is
  invisible. `cmd_doctor` — whose entire purpose is diagnosis — imports no
  logging and shares no channel with the module that would have recorded why a
  source died. It substitutes `type(e).__name__` (`cli.py:243`), i.e.
  `requests`' exception vocabulary, for `httpclient.FetchResult.error`
  (`httpclient.py:105`), which is the pipeline's own.
- **Fix:** configure logging once in `cli.main()` (`cli.py:312`), and have
  `cmd_doctor` report `FetchResult.error` rather than a bare exception class.

### S3 — `bool(os.environ.get(var))` treats `""` as absent and `"0"` as present

- **Where:** `cli.py:211`.
- **Breaks:** verified behaviour:
  ```
  SCRAPER_EMAIL=''       -> present=False
  SCRAPER_EMAIL='0'      -> present=True
  SCRAPER_EMAIL=' '      -> present=True
  SCRAPER_EMAIL='false'  -> present=True
  SCRAPER_EMAIL='None'   -> present=True
  ```
  A GitHub Actions secret set to whitespace, or a `.env` line like
  `GOOGLE_PLACES_API_KEY=0`, passes doctor's gate — and `httpclient.py:81` /
  `google_places.py:157` will happily use `"0"` as an API key or as the contact
  address in the User-Agent. `present` should be `bool((os.environ.get(var) or
  "").strip())`.
- **Related, and inconsistent:** `cmd_doctor` reads `os.environ` *directly*, but
  the only consumer of `SCRAPER_EMAIL` derives its value from
  `os.environ.get("SCRAPER_EMAIL", "")` at `httpclient.py:81`, and caches the
  result **per thread** inside the thread-local Session (`httpclient.py:63-71`).
  In a long-lived process, a Session created before the variable was exported
  keeps an anonymous UA forever. `doctor` reporting `OK` is therefore not
  evidence that any live Session will use the address.

### S3 — `pyproject.toml:33` bakes the flat layout into the console-script entry point

- **Where:** `pyproject.toml:32-33` (`leadminer = "cli:main"`) and
  `pyproject.toml:35-37` (`include = ["scrapers/"]`, whose comment reads *"The
  package imports a top-level sibling module, so both must ship."*).
- **Breaks:** installing this project writes seven top-level modules into
  `site-packages`: `cli`, `main`, `dedup`, `enricher`, `httpclient`,
  `pitch_recommender`, `scrapers`. `cli`, `main` and `dedup` are generic enough
  to collide with, or be shadowed by, unrelated packages on the same interpreter.
  The console script cannot be moved to a package-qualified target
  (`leadminer.cli:main`) until the module it names exists as one.
- **Trigger:** `pip install .` into an environment that already contains any
  distribution providing a top-level `main` or `cli` module; `import cli`
  resolves by `sys.path` order, and `leadminer doctor` runs someone else's
  `main`.
- **Fix:** move to `src/leadminer/` and set `leadminer = "leadminer.cli:main"`.
  Note that `cli.py`'s function-local first-party imports (`cli.py:35, 46-49,
  249-252`) must become `from . import main` / `from .scrapers.osm import
  OSMScraper`. They can stay function-local — see §3 — but they can no longer be
  bare top-level names.

## 3. Why the function-local import style is load-bearing (do not hoist it)

Every first-party import in `cli.py` is inside a function body: `cli.py:35`
(`main`), `:46-49` (`scrapers.*`), `:249-252` (`main`, `enricher`,
`pitch_recommender`, `scrapers.whitelist`). Module scope holds stdlib only
(`cli.py:18-24`). That is not a style accident — it is the only thing keeping
`import cli` from transitively loading `scrapers.google_places` →
`enricher` → `httpclient` → `requests` before `argparse` runs
(`cli.py:280`). Hoisting any of them to module scope makes every `leadminer`
subcommand pay the full scraper import cost, including the
`GOOGLE_PLACES_API_KEY` read at `scrapers/google_places.py:157` and the
`itertools`-scale query-string constants at `google_places.py:46-125`.

**Keep it function-local across the src-layout migration.** If a future
refactor needs a shared first-party name at module scope, put it in the new
`endpoints.py` / `config.py` (S1 fix) rather than in `main`.

## Not a bug, but worth knowing

- **`cli.py:225-231` is good practice and should be the template.** Guarding
  `import requests` so that the diagnostic tool cannot itself raise `ImportError`
  is the right instinct, and the comment at `:228-229` states the invariant
  clearly. It just needs extending to `pathlib` (S2 above).
- **`requests` is imported inside a `try`, not for typing and not for logging.**
  For `cmd_doctor` it is a genuine runtime dependency at `cli.py:239`. The
  `try/except ImportError` is a deliberate, documented degradation path and the
  only correctly-guarded dependency in the function.
- **The 403/429 blind spot is a threshold bug, not a layering bug, and the two
  fixes are independent.** `cli.py:240`'s `status_code < 500` predicate is wrong
  for all three upstreams independently of any import question. Fixing the
  threshold makes doctor *less* wrong; routing through `httpclient` (S1/S2
  above) makes it *correct*. Both are needed. `247-x.md` covers the threshold.
- **`scrapers/google_places.py:26` (`from enricher import infer_region`) is the
  graph's one genuine layering inversion**: a *source* module importing a
  *downstream pipeline stage*. It is acyclic today only because
  `enricher.py:128` imports nothing but `httpclient`. `infer_region` belongs in
  a shared geo/region module beside `dedup` and `whitelist`. It is not on
  `cmd_doctor`'s critical path today, but it is the second edge most likely to
  close a cycle during the S1 refactor, after `httpclient → scrapers.*`.
- **`requirements.txt` still pins `beautifulsoup4==4.12.3` and `lxml==5.2.2`,
  which are imported by no `.py` file in the tree** (`grep -rn 'bs4\|BeautifulSoup\|lxml' --include='*.py' .`
  → no matches), while CI installs from that file rather than from
  `pyproject.toml`. So the environment `doctor` inspects is not the environment
  `pyproject.toml` declares. `030-packaging-import-hygiene.md:15` raised this
  before `pyproject.toml` existed; it is still open.
- **`doctor` has zero test coverage.** `tests/test_lead_signal.py` covers
  `cmd_stats` and `cmd_validate` (`:215`, `:232`, `:246`, `:259`) and nothing
  else in `cli.py`; `087-SYNTH-test-gap.md:19` names `cmd_doctor` in the gap
  list. Every finding above is trivially testable with a stubbed `requests`
  module in `sys.modules` — that is how the exit-code and `stat()` results in
  this report were obtained, with no network access.

## Recommended order of work

1. **Break the cycle before fixing anything in `cmd_doctor`.** Add
   `src/leadminer/endpoints.py` exporting `OVERPASS_URL`, `SPARQL_ENDPOINT`,
   `PLACES_API_URL`, `GOOGLE_PLACES_API_KEY_ENV`, `SCRAPER_EMAIL_ENV`, and an
   `OUTPUT_FILES` tuple. Re-point `osm.py:9`, `wikidata.py:9`,
   `google_places.py:30`/`:157`, `httpclient.py:81`, `cli.py:210`/`:233-237`,
   and add `OUTPUT_FILES` beside `FIELDS` at `main.py:33` and use it at
   `main.py:209-213`. Keep `httpclient` a leaf. Until this lands, the correct
   doctor fix is unreachable.
2. **Route doctor's probes through `httpclient`.** `cli.py:239` →
   `fetch_with_retry("GET", url, retries=1, timeout=5)` with the endpoints from
   step 1. This alone makes the Overpass and Wikidata rows meaningful, because
   the request finally carries the User-Agent the pipeline sends.
3. **Make the exit code real.** Fold the three probe results and the
   `DATA_DIR` checks into `ok` at `cli.py:208-244`. Independently of the layering
   work this is the highest-value one-line change in the file; with step 2 it
   becomes trustworthy.
4. **Widen the status predicate** from `< 500` to a real expectation per
