# 224 — `cmd_stats` (cli.py:79): input-dependent wrong and surprising output

## Verdict

The counting arithmetic is fine; the **input contract is not enforced anywhere**. `cmd_stats`
is the designated first-line diagnostic ("This is the first thing to check", `cli.py:80`), yet
it will cheerfully report `with phone : 0` for a file full of phone numbers, and
`website live : 0 / website dead : 0` for a master where 900 sites are live — both with exit
code 0, because nothing ever compares the file's header against the 22 columns the code asks
for, and the `website_live` comparison is an exact string match against `"True"`/`"False"`.
Everything else is truncation, blank-key rendering, or an uncaught traceback. The function is
correct **only** for bytes written by `main.write_csv` (`main.py:124-127`) and by nothing else;
that invariant is stated and defended under *Not a bug* below.

All findings below were reproduced by importing `cli.cmd_stats` and executing it against
crafted CSVs in a temp directory. No network calls; no repo files modified. Reproduction
scripts: `/private/var/folders/x_/ljryhzvn18s0r2_1j4kf_1kc0000gn/T/opencode/stats_probe/probe{,2,3,4}.py`
(Python 3.14.8; note `requests` is not installed in this environment, which is itself a
useful fact — see S2-6).

## Findings

### S1 — `website live`/`website dead` are exact-string matches, so one spelling variant zeroes the entire liveness block

- **Where:** `cli.py:107-110`
- **Breaks:** `(r.get("website_live") or "").strip() == "True"` matches exactly one
  spelling. `TRUE` (what Google Sheets writes after a human opens the file — Sheets
  type-detects the text `True` into a boolean and re-exports it as `TRUE`), `true`, `False`,
  `FALSE`, `yes`, `1`, and the string `"None"` all match *no* counter. Since `unknown` at
  `cli.py:110` also requires the cell to be blank, those rows vanish from all three numbers:
  `live + dead + unreachable` no longer equals "with website". The block reads as
  authoritative and is wrong.
- **Trigger:** the master has been through Drive/Sheets. 900 rows with
  `website_live=TRUE`, 300 with `website_live=FALSE`.
- **Wrong output (actual, verified):**
  ```
    with website    : 1,200
    website live    : 0
    website dead    : 0
    unreachable     : 0  (not the same as dead)
  ```
  `with website: 1,200` immediately above `live: 0, dead: 0, unreachable: 0` is
  self-refuting, and `cmd_stats` exits `0`. An operator concludes "every site is
  unreachable" or "the enricher is broken", when in fact the file is fine and only the
  spelling changed. Same result for `website_live` = `"None"` (2 rows with websites →
  `live: 0, dead: 0, unreachable: 0`).
- **Fix:** parse case-insensitively and account for the residue —
  `wl = (r.get("website_live") or "").strip().lower()`, match `wl in {"true","1","yes"}` /
  `{"false","0","no"}`, and print an explicit `unrecognised website_live: N` line when the
  three counters still don't sum to `with website`.

### S1 — No schema check: a CSV whose columns `cmd_stats` cannot find is reported as confident all-zeros

- **Where:** `cli.py:86-96` (`count()` uses `r.get(field) or ""`, which yields `None` for a
  missing key → `""` → falsy), plus `cli.py:116/120/129` where a missing key becomes the
  literal label `None`.
- **Breaks:** `csv.DictReader` keys rows by the file's header. If the header is missing,
  renamed, reordered by a re-export, or simply not the pipeline's 22 columns, every lookup
  returns `None`. `count()` then returns `0` for every field and `total` is off by one (the
  first data row is consumed as the header). Nothing detects this, and the function returns
  `0`.
- **Trigger:** a headerless dump — the most common shape for a file a sales rep pulled out of
  a spreadsheet:
  ```
  Cafe,+96170123456,https://a.example
  Shop,+96170654321,https://b.example
  Gym,+96170999999,
  ```
- **Wrong output (actual, verified):**
  ```
  c2.csv  (2 rows)

    with phone      : 0
    with email      : 0
    with website    : 0
    with region     : 0
    website live    : 0
    website dead    : 0
    unreachable     : 0

    by priority:
      None       2
    by source:
      None                         2
    by region:
      Unknown              2
  ```
  Row count is also wrong (2, not 3), and the `None` labels read like a source literally
  named `None`. Same output for a valid-but-different schema (`name,phone,website` only) and
  for pure garbage (`just,some,values`): `rc=0`, every metric `0`, every bucket `None`.
- **Fix:** after `csv.DictReader`, assert the header against `main.FIELDS` (importable
  without `requests` if you move `FIELDS` to a dependency-free module) and fail loudly:
  `missing = [f for f in FIELDS if f not in reader.fieldnames]` → print and `return 2` if
  `phone`/`name`/`website` are among them.

### S2 — `by source` reports merged source **sets**, not sources; per-source attribution is unrecoverable

- **Where:** `cli.py:120-121`
- **Breaks:** `dedup._pick` rewrites `source` into a pipe-joined sorted union of every source
  that saw the business (`dedup.py:174`), and `main.py:180-209` writes the *deduped* set to
  disk. So `Counter(r.get("source"))` buckets by source-combination. A record found by both
  Google and OSM counts once, under `google_places|osm`, and appears in neither per-source
  total. This is the block an operator uses to answer "which scraper is degrading?", and it
  cannot answer it.
- **Trigger:** 1000 records from `google_places`, 900 of which OSM also matched. Run through
  the real `dedup.dedup()` and written to CSV.
- **Wrong output (actual, verified):**
  ```
  o.csv  (1,000 rows)
    by source:
      google_places|osm            900
      google_places                100
  ```
  Ground truth is google_places 1000, osm 900. The true OSM contribution (900) appears nowhere;
  the true Google contribution (1000) appears as 100.
- **Fix:** split the field before counting —
  `collections.Counter(s for r in rows for s in (r.get("source") or "").split("|") if s)` —
  and label the block "by source (records may appear under several sources)".

### S2 — `most_common(12)` / `most_common(8)` silently drop buckets, while `by priority` has no cap at all

- **Where:** `cli.py:116` (`.most_common()`, uncapped), `cli.py:120` (`most_common(8)`),
  `cli.py:124-125` (`most_common(12)`), `cli.py:129-130` (`most_common(8)`)
- **Breaks:** three of the four counters truncate with no `+N more` marker, and the two caps
  are below the cardinality of their own domains. `enricher.py:10-76` defines **13** distinct
  regions (8 Lebanese + 5 Saudi) plus `Unknown` = 14 buckets against a cap of 12.
  `pitch_recommender.py:58-99` defines **11** distinct services against a cap of 8.
- **Trigger (a):** one row per region, all 13 populated.
- **Wrong output (actual, verified):** `by region` prints 12 lines; `Medina` is missing, and
  there is no indication that anything was dropped. Adding a single blank-region row (so
  `Unknown` is present) makes it 14 buckets into 12 slots.
- **Trigger (b):** one row per possible `recommended_service`.
- **Wrong output (actual, verified):** `top pitches` prints `8 of 11` distinct pitches
  present. `Full digital launch (brand + website + social setup)` and the two below it are
  silently absent — and those are exactly the high-value pitches a rep cares about.
- **Trigger (c):** a `industry_priority` column polluted with 500 distinct values.
- **Wrong output (actual, verified):** `by priority` emits **501 lines** — unbounded. So the
  same function is simultaneously lossy in one block and unbounded in another, and neither
  behaviour is documented.
- **Fix:** print `(len(counter) - shown)` buckets as `... and N more`, and raise the region
  cap to cover the domain (`most_common(len(counter))`, or 20).

### S2 — Unhandled exceptions produce a raw traceback, not a diagnostic: a directory argument and any non-UTF-8 file

- **Where:** `cli.py:86-87` (bare `open`, no `try`), `cli.py:82` (`.exists()` accepts
  directories), `cli.py:312-318` (`main()` catches only `KeyboardInterrupt`)
- **Breaks:** `path.exists()` is `True` for a directory, so the guard at `cli.py:82` passes
  and `open()` explodes. `encoding="utf-8-sig"` is hard-coded, so any file that is not
  UTF-8 explodes on the first non-ASCII byte. Both escape as tracebacks out of a tool whose
  entire job is to explain broken state.
- **Trigger:** `leadminer stats data` (one keystroke from the documented default
  `data/all_businesses.csv`).
- **Wrong output (actual, verified):**
  ```
  IsADirectoryError: [Errno 21] Is a directory: '/…/data'
  ```
- **Trigger:** a CSV exported from Sheets/Windows in cp1256, containing Arabic
  (`مقهى,+96170123456,https://a`), or any file with a stray `0xFF` byte.
- **Wrong output (actual, verified):**
  ```
  UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe3 in position 19: invalid continuation byte
  ```
  The Arabic-name case is the dangerous one: it is exactly the file a Lebanon-market rep
  downloaded from Drive, and the failure mode is an operator being told their data is
  corrupt rather than that the tool is.
- **Fix:** `if not path.is_file(): return 2`, and wrap the read in
  `except UnicodeDecodeError` to retry with `encoding="utf-8", errors="replace"` and warn that
  N bytes were lost.

### S2 — `leadminer stats` cannot reproduce `main.py`'s own summary, so the offline tool and the run log disagree

- **Where:** `cli.py:98-131` (whole reporting surface)
- **Breaks:** `main.py:219-242` prints `SALES-READY (actionable)` and a *sales-ready-filtered*
  service breakdown. `cmd_stats` prints neither the sales-ready count nor the qualifying
  breakdown, and its `top pitches` is over **all** rows. An operator comparing the run log to
  `leadminer stats` sees two different "top pitches" numbers and no way to tell which is
  which. `cmd_stats` also ignores 8 of the 22 shipped columns entirely, including
  `completeness_score`, `lead_score`, `rating`, `review_count`, and two outreach channels
  (`linkedin`, `facebook`).
- **Trigger:** `leadminer run` writes its summary, then the operator runs
  `leadminer stats data/all_businesses.csv`.
- **Wrong output:** not a wrong number, but two mutually inconsistent "top pitches" tables
  with no provenance label, and the single KPI the business actually runs on
  (`main.py:226`) is absent from the offline tool.
- **Fix:** add a `sales-ready: N` line computed with `main.has_any_contact` semantics, scope
  `top pitches` to that subset (or label it `all rows`), and print a `by country:` block.

### S3 — `total` counts structurally blank rows; there is no key-integrity check

- **Where:** `cli.py:92-93`
- **Breaks:** `csv.DictReader` skips truly blank lines but happily yields rows for a line of
  nothing but commas — the artefact every Excel/Sheets round-trip leaves behind. Those rows
  inflate the headline row count and land in the blank buckets.
- **Trigger:** 10 real rows + 2 all-empty comma rows.
- **Wrong output (actual, verified):** `ac.csv  (12 rows)` and `by region: Unknown 3` /
  `by source: (blank) 2`. With 50 such rows: `rc=0`, `z.csv  (50 rows)`, every count `0`, every
  bucket `50` — a fully successful-looking report on a file containing zero businesses.
- **Fix:** count `rows = [r for r in reader if any((v or "").strip() for v in r.values())]`
  and print `dropped N blank rows` when anything is removed.

### S3 — `DATA_DIR` is CWD-relative, so the documented bare `leadminer stats` only works from the repo root

- **Where:** `cli.py:26` (`DATA_DIR = pathlib.Path("data")`), `cli.py:294` (parser default),
  also affects `cmd_doctor` at `cli.py:217-222` and `main.py:41`
- **Breaks:** the default `data/all_businesses.csv` is resolved against the process working
  directory. Installed as a console script (`pyproject.toml:33`) and invoked from anywhere
  else — a cron entry, a `cd`-first shell, `gh workflow`-style invocation — it always fails.
- **Trigger (actual, verified):** a directory containing `data/all_businesses.csv`:
  ```
  cwd=<dir with data/>   rc=0  data/all_businesses.csv  (3 rows)
  cwd=<dir without it>   rc=2  no such file: data/all_businesses.csv
  cwd=/                  rc=2  no such file: data/all_businesses.csv
  ```
  The message blames a missing file rather than a missing working directory.
- **Fix:** anchor `DATA_DIR` to the package (`pathlib.Path(__file__).resolve().parent / "data"`)
  and fall back to the CWD-relative path only if that does not exist.

### S3 — `count()` and the histograms use two different definitions of "blank"

- **Where:** `cli.py:96` (`(r.get(field) or "").strip()`) vs `cli.py:110`
  (`r.get("website") and ...`, truthiness, no `strip()`), and `cli.py:124`
  (`r.get("region") or "Unknown"`, truthiness)
- **Breaks:** the headline counts strip whitespace; the gated histograms do not. A
  whitespace-only cell is "absent" in one place and its own bucket in the other, so the
  counts and the breakdowns disagree with each other.
- **Trigger:** rows with `website=" "` and `website="  "`, plus one genuinely live site.
- **Wrong output (actual, verified):**
  ```
  with website    : 1
  website live    : 1
  unreachable     : 2  (not the same as dead)
  ```
  `unreachable (2) > with website (1)`. The same split shows in `region`: a whitespace-only
  region gives `with region : 1` while `by region` lists a whitespace bucket and never emits
  `Unknown`.
- **Fix:** define one `_present(value)` helper (`isinstance(v, str) and bool(v.strip())`) and
  use it in `count()`, in the `unknown` predicate, and in the `or "Unknown"` fallbacks.

### S3 — The whole file is materialised; peak RSS is ~8.7x the file size

- **Where:** `cli.py:87` (`rows = list(csv.DictReader(f))`)
- **Breaks:** `cmd_stats` is the tool you point at the cumulative master, which grows without
  bound (`main.py:150` loads it, `main.py:209` writes it back). `main.load_master` streams
  (`main.py:85-104`); `cmd_stats` does not, and every count is expressible as a single pass.
- **Trigger (actual, verified):** a 45.2 MB, 200,000-row master.
- **Wrong output:** `maximum resident set size 393,232,384` bytes (393 MB, 2.89 s wall) for
  45 MB of input. Extrapolating the project's own scale targets, a 500k-row master costs
  ~1 GB in a tool an operator runs by hand to look at a number.
- **Fix:** iterate the reader once, accumulating counters, and never hold `rows`.

### S3 — `_fmt`'s `"n/a"` branch is unreachable, and blank / `None` keys render as invisible labels

- **Where:** `cli.py:29-30` (`_fmt`), `cli.py:116-117`, `cli.py:129-131`
- **Breaks:** `count()` returns `sum(...)` over a bool generator and is therefore always an
  `int`, so `_fmt(None)` never fires — `"n/a"` is dead code. Meanwhile `str(None)` prints as
  the literal four characters `None`, and `str("")` prints as nothing at all, producing
  output like:
  ```
  top pitches:
    SEO audit                                            1
    Google Business Profile                              1
                                                           1
  ```
  The third line is a blank pitch bucket rendered as whitespace plus a count.
- **Fix:** drop the `None` arm from `_fmt`; map falsy keys to a literal `(blank)` /
  `(missing)` before printing in all four counter loops.

### S3 — `website` and `website_live` are merged independently, so the liveness verdict can describe a discarded URL

- **Where:** `cli.py:107-108` reporting on data produced by `dedup.py:159-195`
- **Breaks:** `_merge` picks `website` and `website_live` in separate `_pick` calls with
  separate rank tuples (`dedup.py:114` marks both `_VOLATILE`, but they rank on different
  keys: `_trust_for("website")` differs per source at `dedup.py:97-110`, whereas
  `website_live` has no per-source trust entry and falls back to `_DEFAULT_TRUST`). The
  surviving pair can therefore mix a URL from one observation with a liveness verdict
  obtained by fetching a *different* URL.
- **Trigger (actual, verified):**
  ```python
  a = {phone:"+96170123456", source:"osm",            website:"https://old.example",
       website_live:None,    scraped_at:"2026-02-01…"}
  b = {phone:"+96170123456", source:"google_places",  website:"https://new.example",
       website_live:True,    scraped_at:"2026-01-01…"}
  dedup([a, b])[0]  ->  website="https://old.example", website_live=True
  ```
  `True` was obtained by fetching `https://new.example`, which the merge threw away.
- **Wrong output:** `leadminer stats` reports `website live : 1` for a site that was never
  checked. This is a `dedup` defect, not a `cmd_stats` one, but `cmd_stats` is where it
  becomes visible and unfixable downstream.
- **Fix:** in `_pick`, treat `website_live` as bound to `website` — if the surviving `website`
  differs from the record that supplied `website_live`, reset `website_live` to `None`.

## Not a bug, but worth knowing

- **The tri-state fix at `cli.py:105-113` is correct, and here is the exact invariant that
  makes it correct.** `main.write_csv` (`main.py:125-127`) serialises with `csv.DictWriter`,
  which writes a `None` as the empty cell and a Python `bool` as exactly `"True"` or
  `"False"`. There are exactly two producers of `website_live` in the codebase —
  `enricher.py:250` (`True if LIVE else (False if DEAD else None)`) and `main.py:103`
  (`True if wl == "True" else (False if wl == "False" else None)`) — and both can only emit
  `True`, `False`, or `None`. Therefore, for any file whose `website_live` column was written
  by `write_csv`, `strip()` returns one of `{"", "True", "False"}`, each row matches exactly
  one of `cli.py:107/108/110`, and `live + dead + unreachable` equals the number of rows with
  a non-blank website. Collapsing blank into `False` really would have been wrong, and the
  comment records that. **The invariant holds only for bytes `write_csv` produced** — one
  hand edit, one Sheets round-trip, or one other writer breaks it, and `cmd_stats` has no way
  to notice. That is exactly the gap S1 exploits.
- **`utf-8-sig` on read matches `utf-8-sig` on write.** `cli.py:86` agrees with
  `main.py:124`, so a master written by the pipeline is read without a BOM glued to `name`.
  Correct, and the same reasoning as `main.py:82-84`. (`cmd_validate:154` still exists to
  catch masters written by something else — but it only checks `name`, and it does not check
  `website_live`, so no offline command catches S1.)
- **Ragged rows are handled gracefully.** A truncated final line
  (`ShortRow,+96170`) and a short row in the middle both land as `None` from DictReader's
  `restval` and are counted correctly by `count()`'s `(r.get(field) or "")` guard. No crash,
  no exception.
- **Empty inputs are handled correctly.** A zero-byte file and a header-only file both return
  `1` with `<path> is empty` on stderr (`cli.py:88-90`). A missing file returns `2`
  (`cli.py:82-84`).
- **Deferring imports is genuinely good and I verified it works.** `requests` is *not
  installed* in this environment, and `cmd_stats` ran fine — `cli.py:35/46-49/249` all defer
  their imports so `stats` and `validate` work in a bare interpreter, which is the right
  property for a diagnostic. One caveat for the README's claim (README.md:19) that `score`
  "never touches the network": `cmd_score` at `cli.py:249` does `import main`, which reaches
  `main.py:25` → `scrapers/osm.py:4` → `httpclient.py:43` → `import requests`. It makes no
  network calls, but it will not run at all without the HTTP stack installed, so `score` and
  `stats` do not have the same failure surface.
- **`cmd_stats` never validates anything by design; `cmd_validate` is the gate.**
  `validate` (`cli.py:135-201`) returns `1` on bad data, `stats` returns `0` on garbage. The
  separation is defensible, but it means S1-1 and S1-2 both escape to a human reading
  confident numbers. Neither command cross-checks the other's output.

## Recommended order of work

1. **S1-2 first — add a header check.** One `missing = [f for f in FIELDS if f not in reader.fieldnames]`
   guard at `cli.py:87` closes the largest class of silent-wrong-output (headerless,
   renamed, foreign-schema files) and costs three lines.
2. **S1-1 second — stop string-matching `website_live`.** Lower-case the cell, accept
   `{true,1,yes}` / `{false,0,no}`, and print an `unrecognised: N` line whenever
   `live + dead + unreachable != with website`. That last assertion is the real safety net:
   it turns any future spelling drift into a visible non-zero instead of a confident zero.
3. **S2-3 — split `source` on `|` before counting**, so the block answers "which scraper is
   degrading?" (4 lines at `cli.py:120`).
4. **S2-4 — add `... and N more` to all four counters** and raise the region cap to 20 so
   `enricher.py`'s 13 regions and `pitch_recommender.py`'s 11 pitches both fit; cap
   `by priority` at 20 to match.
5. **S2-5 — `path.is_file()` and an `except UnicodeDecodeError` fallback** so the diagnostic
   never tracebacks.
6. **S3-7 / S3-9 — one `_present()` helper plus a blank-row filter**, which fixes the
   inflated `total` and the `unreachable > with website` contradiction together.
7. **S3-8 — anchor `DATA_DIR` to the package** so `leadminer stats` works from any directory.
8. **S3-10 — one streaming pass** that drops `list(...)` and the whole `rows` list.
9. **S2-6 and S3-11/S3-12 — cosmetic, but do them last**: they change output shape and are
   cheap to churn through once the numbers underneath are trustworthy.
10. **S3-12's underlying `dedup` defect should be filed against `dedup._merge`**, not here —
    it corrupts the exported data, not just this report.
